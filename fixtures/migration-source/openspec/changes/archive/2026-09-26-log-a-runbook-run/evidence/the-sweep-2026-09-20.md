# The sweep: every defensive measure, and where the same input class flows

**The instruction was to find the pattern before fixing the symptoms.** Three of the twelve findings
are the same shape — *a lesson this project already learned, stated in one place and not applied in
the sibling* — which is the shape that made the predecessor's guard fail open twice. So this is the
sweep, run before any fix, in both directions:

1. for every defensive measure `runs.rs` applies **anywhere**, where else does the same input class
   flow, and is it applied there too;
2. for every measure the **rest of the codebase** applies, should `runs.rs` have inherited it.

**The negative list is the point.** Nine places were checked and found clean, and they are listed
with why, because that list is what stops the thirteenth finding.

---

## Direction 1: measures `runs.rs` applies somewhere

### `escape_text` — applied to two of three inputs. **Two new instances found.**

| Site | Input | Escaped? |
| --- | --- | --- |
| `masthead` 534-535 | runbook name, record name | yes |
| `shell` 669 | runbook name, record name | yes |
| `record_section` 636 | **copied requirement id, into element content** | **no** — finding 1 |
| `record_section` 635 | copied requirement id, into `data-refs` attribute | **no** — *not* in the review's list |
| `record_section` 634/637 | derived `verify-*` id, into attribute and content | **no** — *not* in the review's list |

**The review's finding 1 names one of these three. The sweep found the other two.** The attribute
sites were not reported because `kuchikiki`'s attribute serialization escapes `&` and `"` on the way
*out* — but these strings never go through a tree, they are interpolated into a source string that is
then parsed. So a requirement id containing `"` closes the attribute:
`data-refs="req-a" onload="..."` is reachable by the same route as the script injection.

**And the escaping helper itself is a duplicate the sweep found.** `htmlspec-assets/src/lib.rs:669`
already has `escape_text`, and at 676 it has **`escape_attribute`** — the same pair, private, used by
`render_kind` for exactly this job. `runs.rs` reimplemented the text half and did not implement the
attribute half at all. That is the stated-once-applied-once pattern at the level of the *helper*
rather than the call site, and it is why the attribute sites were missed: the tool for them did not
exist in this file.

**Fix:** make the assets pair public and use it, rather than growing a third copy.

### `symlink_metadata` over `Path::exists` — **one new instance found, pre-existing**

`commands.rs:754` explains this in the project's own words: `Path::exists` follows symlinks and
reports `false` for a broken one, which is how the archival guard failed open a third time.

| Site | Uses | Verdict |
| --- | --- | --- |
| `runs.rs:116` | `path.exists()` before writing a record | **finding 2**, measured |
| `commands.rs:577` (`write_document`) | `path.exists()` before writing a document | **the same defect, pre-existing** |

**Measured, on the unmodified binary:**

```
$ ln -s ../../../../ESCAPED-BY-NEW.html htmlspec/changes/c/tasks.html
$ htmlspec new document tasks htmlspec/changes/c/tasks.html --subject X
htmlspec/changes/c/tasks.html: created a tasks          exit 0
$ ls -la /tmp/ESCAPED-BY-NEW.html
-rw-r--r--  2813  /tmp/ESCAPED-BY-NEW.html
```

**So `htmlspec new document` writes outside the project through a broken symlink, and has since
before this change.** Not mine, and not silently fixed either: `write_document` is on the path of
`new document` and `new change`, both of which this change does not touch. Reported to the lead as a
separate finding rather than folded in — a fix there needs its own regression test through `new
change` as well, and bundling it would put an unreviewed change to a shipped command inside a change
about run records.

`runs.rs:116` **is** fixed here, with `symlink_metadata`, and the fix is the same three-arm match
`refuse_a_runbook` uses: `NotFound` proceeds, any other error refuses, and anything present refuses.

### The recovery-free gate — **applied to one of five parse sites**

`compose` gates `tasks.html` at 406 and not `specification.html` at 421, twelve lines later. That is
finding 10. The sweep found three more parse sites with no gate:

| Site | Parses | Gated? | Verdict |
| --- | --- | --- | --- |
| `compose` 402 | the runbook's procedure | yes | correct |
| `compose` 421 | the runbook's contract | **no** | finding 10 |
| `requirement_ids` 319 | the contract, in `--check` | **no** | **new** |
| `recorded_ids` 343 | each record, in `--check` | **no** | **new** |
| `count` 382 | the record just composed | no | **correct, and stated** — that source was composed here and already formatted, so recovery would be a defect in this program; a gate would be checking our own output |

The two new ones are the same defect as 10 on the read path rather than the write path, and they are
what the review's note under finding 5 — *"`--check` never validates the records it reads"* — points
at. A record whose markup needs recovery has more than one reading, and `--check` currently picks one
silently and reports conformance from it.

### `is_a_name` — **applied to every name. Clean.**

Three names reach a path: the runbook and record in `start`, the runbook in `check`. All three
checked. **A fourth candidate exists and correctly is not checked**: the derived `verify-*`
identifier never reaches a path, only markup — and markup is the escaping question above, not the
path question.

### `has_class` ancestor skip — **clean, and one case it does not cover**

`units_of` skips a node whose ancestor carries the same class, so a nested unit is not copied twice.
Checked both classes it is called with: a `requirement` holds `scenario`s (different class, so no
skip needed and none happens), and a `task` holds nothing. **Clean.** The skip is defensive against a
vocabulary change rather than against a present case, which the comment says.

### `settle_change_states` — **one case it gets wrong, which is finding 11 and worse than reported**

The rewrite is unconditional. For `added` and `modified` it is right. For **`removed`** it produces
`data-change="unchanged"` beside a `data-reason` that says the unit is withdrawn — two attributes
contradicting each other.

**The review calls this a MEDIUM. The schema makes it worse than that.** `document.schema.json`'s
`changeState` description states that for `removed`, *"no reference may target it"* — and
`refs/removed-target` is an **error**, not a warning:

> `this {} references {target}, which this change withdraws. Work cannot target an obligation that
> is being removed`

So the correct handling is not "leave the state alone". A `removed` requirement must not be copied at
all: copying it and writing a verification naming it would be a `refs/removed-target` error if the
state were preserved, and a silent contradiction if the state is rewritten. **Both branches are
wrong, which means the unit is excluded**, and that is the fix.

## Direction 2: measures the rest of the codebase applies

### `write_document`'s order: compose, validate, **then** write — **not inherited. Finding 7/8.**

`commands.rs` validates at 654 after writing at 645, and its comment says the file is left in place
*"so a contributor can see what it produced"* — which is defensible for a template defect, because
the template is this program's and the contributor can do nothing about it.

**It is not defensible here**, and the review's second structural point is right: the fault in every
case measured — missing id, injected markup, id collision — is in the **runbook**, which the
contributor *can* fix. So the record must never reach disk. Reordering also fixes the wedge (the
`exists` refusal blocking a retry) and the `--json` payload announcing success on a run that exits 2.

**And it fixes finding 1's worst property**: the injected-script record never exists on disk at all.

### `validate_source_at` resolving a real store — **inherited. Clean.**

Already used, which is the strong form of the promise.

### `assets_prefix_for` deriving from the project — **inherited. Clean.**

### `path_of` reading the asset table rather than spelling an address — **inherited. Clean.**

### `schema_facts` over literal schema values — **inherited, and one hole**

`has_run` reads the outcome vocabulary from the schema rather than writing `"not-run"`, which is the
right discipline. **But it fails open on a value the schema does not enumerate** — finding 5,
measured: `data-outcome="notrun"` reports conformance, because the filter keeps schema values
containing `not` and an unknown string matches none of them.

The fix is not a literal; it is to ask the right question. `has_run` should mean *"this outcome is one
the schema enumerates, and it is not the not-run one"* — so an unrecognized value is not a recorded
outcome. The schema is still the source of the vocabulary.

### `Store::discover` walking upward — not applicable; `runs.rs` does not resolve stores itself.

### The `Refusal` enum's per-operation reasons — **not applicable, and worth saying.** `runs.rs` has
one operation per message, so there is no shared sentence that could be false for a second caller.

### `active_changes`'s `archive` name filter — **not applicable.** `gather` reads `runs/`, which holds
only records.

### `completion`'s tolerance of an unreadable document — **checked, and the precedent cuts the other
way.** `commands.rs:2150` uses `.ok()?` and returns `None`, which the enumeration then reports as *a
change with no tasks document* — a distinction it makes deliberately. `gather`'s `.ok()?` at 309
drops the entry entirely, so an unreadable record becomes **an absent record**, which is finding 6.
The precedent shows the project's habit is to preserve the distinction, and `gather` loses it.

## The count

**Twelve findings reported. The sweep found four more**, all instances of the three patterns the lead
named:

1. the `data-refs` attribute interpolation (escaping, attribute half);
2. the derived `verify-*` id interpolation (escaping, both halves);
3. `requirement_ids` and `recorded_ids` parsing without the recovery gate (the read path);
4. `write_document`'s identical symlink escape — **pre-existing, reported, not fixed here**.

And one pattern found at a level the call-site sweep would have missed: **`escape_attribute` already
exists in `htmlspec-assets` and `runs.rs` had no attribute-escaping function at all**, which is why
the two attribute sites were invisible to a reviewer reading `runs.rs` for missing `escape_text`
calls.

**Nine places checked and found clean**, listed above with why: `is_a_name` at all three names, the
`has_class` ancestor skip at both classes, `count`'s deliberately ungated parse, `validate_source_at`,
`assets_prefix_for`, `path_of`, `Store::discover`, the `Refusal` enum, and the `archive` name filter.
