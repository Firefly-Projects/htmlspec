Add a dark theme: the contract

The contract a dark-theme change would establish: what the application must do, and the one decision that makes the second requirement checkable. Hand-authored with no tooling. The case for the change is in the proposal beside this document, and the work is in the tasks document.

Requirements

Theme selection

The application MUST let the user select a light theme or a dark theme.

The selected theme persists

When
The user selects the dark theme.
Then
The application uses the dark theme after the next launch.

The default theme follows the system

Given
A user who has never selected a theme.
When
The application starts.
Then
It uses the theme the operating system reports.

Contrast

Every text and background pair in either theme MUST meet a contrast ratio of 4.5 to 1.

Contrast is measured, not asserted

When
The check suite runs.
Then
It computes the ratio for every declared pair and fails below 4.5 to 1.

Decisions

Themes are CSS custom properties, not two stylesheets

Both themes are one stylesheet, with colors held in custom properties that a data-theme attribute on the root element switches.

Two stylesheets double the surface where a color can be defined and make a missed pair invisible until someone looks. One property table makes the pairs enumerable, which is what lets the contrast requirement be checked mechanically rather than by eye.
