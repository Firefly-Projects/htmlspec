The html-spec foundation change

The settled contract this change established: its requirements, the decisions behind them, the evidence measured, the risks accepted, and the verification recorded. Hand-authored with no tooling. The work that delivered it is in the tasks document beside this one.

Requirements

Markup must be deterministically parseable

A conforming document MUST produce zero recovered parse errors. Validation MUST reject a document whose interpretation depends on parser error recovery.

The parser is pinned exactly, and every permitted recovery MUST carry a project-owned diagnostic code justified by a fixture.

A conforming document reports nothing

Given
A document with a short doctype, a head, a title, and one requirement.
When
The validator parses it.
Then
No recovery is reported and the document is accepted.

An unmapped recovery is fatal

Given
A parser message the enumeration does not name.
When
The validator classifies it.
Then
It reports parse/unmapped-recovery and fails, rather than ignoring the message.

The element contract is published as a machine-readable schema

The projected model MUST be published as a JSON Schema that is the single source of truth for the vocabulary, the required structure, the identifier prefixes, and the permitted attribute values.

The schema alone MUST NOT be treated as the complete public contract, because it describes the model and not the HTML that produces it.

A third party reads the contract

Given
A consumer outside this project.
When
It reads the schema and the projection specification.
Then
It determines every semantic unit and reproduces the model for a fixture.

Decisions

Parse with the browser's grammar, then refuse its forgiveness

Documents are parsed with html5ever, and every recovery the parser reports is a fatal diagnostic.

Requiring XML well-formedness instead would validate a grammar no consumer uses, so a document could be well-formed and still read differently in a browser. Keeping the browser's grammar and discarding its tolerance rejects exactly the documents whose meaning is not determined by their markup.

A third party can derive the vocabulary from the schema alone

The published JSON Schema was to be the whole public contract.

This was too strong. A schema describes the projected model and says nothing about which elements produce it, so an outside implementation reading only the schema could not reproduce the model.

The public contract is three pieces

The contract is the JSON Schema for the projected model, a normative HTML-to-model projection specification, and conformance fixtures that pin the mapping.

Each piece answers a question the others cannot. The schema fixes the shape, the projection fixes the mapping, and the fixtures stop both from drifting from the implementation.

Evidence

A conforming document produces zero recoveries

The task 1.5 spike parsed a ten-document corpus with the pinned parser. The conforming document reported no recovery, and the permitted-recovery allowlist is therefore empty.

This contradicted the risk register, which expected recoveries for benign input. The measurement replaced the expectation.

Type generation is lossy in two measured places

minItems becomes a plain Vec, and a bare const becomes an arbitrary JSON value rather than a string.

Generated types are therefore a convenience for rule code, and the runtime validator is the enforcement layer. Two tests assert the losses, so a later upgrade that closes a gap forces a review.

Risks

The closed vocabulary will prove incomplete

Seven unit types will not cover every real specification, and a vocabulary that cannot express a document pushes meaning back into prose.

Held down by order rather than by an extension mechanism: three documents are hand-authored against the draft before the parser, the formatter, the validator, and the template harden around it.

A parser upgrade can reword a message

The enumeration maps free-text messages, so a reworded message could silently change what the validator accepts.

Held down by prefix matching, a fatal residual code, and a test that fails when the pinned version moves.

Verification

The parse-error enumeration holds against the corpus

Ran cargo test -p htmlspec-parse. Eight tests pass, including the corpus sweep asserting that no fixture produces an unmapped recovery.

The schema and the projection specification agree

Ran cargo test -p htmlspec-schema. Seven contract tests pass, including the one asserting the schema states that it is not the whole contract.

The formatter is a fixed point

Not run. The formatter does not exist yet; group 5 implements it.
