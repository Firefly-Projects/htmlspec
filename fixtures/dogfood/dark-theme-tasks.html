Add a dark theme: tasks

The work the dark-theme change needs, as its own document. Hand-authored with no tooling. This document also carries a decision unit, which a tasks document is permitted to do: the completeness rule constrains what must be present rather than what is allowed.

Tasks

  • Extract every color into the property table

    Served the theme-selection requirement, and had to come first for the reason the decision below records.

  • Add the theme control and persist the choice

    Served the theme-selection requirement, including the case where no choice has been recorded yet.

  • Add the contrast check to the check suite

    Served the contrast requirement. The requirement says the ratio is measured rather than asserted, so this is the task that makes it true.

  • Allow a per-page theme override

    Dropped because no requirement asks for it and it multiplies the pairs the contrast check must cover.

Sequencing

The property table lands before the control

Every color moves into the custom-property table before the theme control is built.

The control is the visible half and the tempting one to build first. Doing it first means the second theme is assembled from colors scattered across the stylesheets, and a missed pair shows up as an unreadable page rather than as a failing check. A decision unit records this here because the sequencing is a choice about the work rather than part of the contract, so it does not belong in the specification.
