Requirements

Formatting is idempotent req-formatting-is-idempotent

Formatting a document SHALL be a fixed point: formatting an already-formatted document SHALL produce byte-identical output. Applying formatting repeatedly SHALL never continue to change the file.

Second pass changes nothing

When
a document is formatted twice in succession
Then
the output of the second pass is byte-identical to the output of the first

Formatted file in version control

Given
a formatted document committed to Git
When
formatting is run again with no content edits
Then
Git reports no changes

Formatting preserves meaning req-formatting-preserves-meaning

Formatting SHALL NOT change a document's semantic content. It SHALL preserve every semantic unit, every identifier, every attribute value, every cross-reference, and the document order of content. It SHALL NOT add, remove, or reorder semantic units.

One kind of attribute value is excepted. Where an asset reference names bytes the project's store does not hold, formatting SHALL fill it with the address of the bytes the toolchain ships. A reference that names bytes the store holds SHALL be left as written, even when the store also holds a newer revision, because the reference records what the document was authored against.

An asset reference SHALL be the value of an attribute through which an element loads an asset. These are the same attributes that document-validation's "An asset reference must match the bytes it names" judges, so the formatter and the validator SHALL NOT disagree about which values are references. A hyperlink is a citation, not something the document loads, and SHALL NOT be filled. Text SHALL NOT be read as an asset reference. Prose that quotes one, whether as characters in a code element or escaped in an example, is content, and formatting SHALL leave it as the author wrote it.

A second exception is made only on a contributor's request. Where the request is made, formatting SHALL add the fallback stylesheet that "A document stays readable when its stylesheet cannot load" describes to a document that lacks one, SHALL replace a fallback whose text differs from the current one, and SHALL change nothing else. It SHALL NOT do so for a document of an archived change or a run's record, which are history, judged by the project the document resolves into wherever formatting is run from, whether reached directly or through a symbolic link. Without the request, formatting SHALL leave a document's fallback present, absent, or stale as written.

A third exception is made only on a contributor's request as well. Where the request is made, formatting SHALL rewrite each asset reference a document carries to the store location of the bytes the toolchain ships for the same asset, SHALL write those bytes into the store where it lacks them, from the copy the toolchain carries, and SHALL make no network request. It SHALL add no reference the document does not already carry. It SHALL leave as written a reference to an asset the toolchain ships no revision of, one whose stored bytes disagree with its address, and one the store holds other bytes for at the current revision's address, and SHALL say how to restore that file. It SHALL NOT rewrite a document of an archived change or a run's record, judged as the second exception judges them. Checking with the request SHALL name each document it would rewrite and write nothing, and SHALL succeed where it would write nothing, blocked references included.

Serialization is canonical req-serialization-is-canonical

For any given document content, there SHALL be exactly one canonical serialization. Attribute order, indentation, line breaking, quoting, character escaping, tag closing, and case SHALL be fully determined by the formatting rules rather than by authoring choices or generator behavior.

Two agents converge

Given
two agents that produce the same semantic document with different attribute order and indentation
When
both outputs are formatted
Then
the two files are byte-identical

Attribute order is fixed

When
a formatted element carries a class, an identifier, and a change state
Then
those attributes appear in the order the formatting rules prescribe, regardless of the order they were written in

Escaping is consistent

When
content contains characters that may be written either literally or as entities
Then
the formatted output uses one prescribed form for each such character

Formatting introduces no diff churn req-formatting-introduces-no-diff-churn

Formatting SHALL NOT widen a diff beyond the units a content edit touched. Editing, adding, or removing a unit SHALL NOT cause the formatter to reflow or reindent unrelated parts of the document.

This requirement constrains the formatter only. It does not promise a minimal Git diff for a given edit. Preserved author line breaks mean a one-line paragraph produces a whole-line change when one sentence changes, and that cost belongs to the line structure rather than to the formatter. Diff minimality SHALL be measured as a separate property.

Editing one requirement

When
the prose of one requirement is revised and the document is formatted
Then
the formatter changes no line outside that requirement

Whole-line change is not a violation

When
one sentence changes inside a paragraph held on a single long line
Then
the diff covers that whole line, and the formatter is still conformant

Inserting a requirement

When
a new requirement is inserted between two existing ones
Then
the diff shows the added requirement and does not rewrite the surrounding requirements

Long prose reflow

When
a sentence within a paragraph is edited
Then
the diff does not rewrap the entire surrounding paragraph or section

Generated content is ordered deterministically req-generated-content-is-ordered-deterministically

Where a document contains content whose order is not authored — such as collected references, indexes, or navigation — that order SHALL be determined by a stable rule. Regenerating such content from unchanged inputs SHALL produce identical output.

Regenerating navigation

When
a document's navigation is regenerated with no content change
Then
the navigation is byte-identical to before

No incidental ordering

When
generated content is produced twice from the same inputs in different runs
Then
the ordering does not vary with iteration order, timestamps, or filesystem order

Formatting can be checked without writing req-formatting-can-be-checked-without-writing

It SHALL be possible to determine whether a document is canonically formatted without modifying it, so that continuous integration can reject unformatted documents.

Check passes

When
a canonically formatted document is checked
Then
the check reports success and the file is not modified

Check fails

When
an unformatted document is checked
Then
the check reports failure, identifies the document, and the file is not modified

Files use a stable text encoding and line ending req-files-use-a-stable-text-encoding-and-line-ending

Formatted documents SHALL use UTF-8 encoding, SHALL use a single prescribed line ending, SHALL end with exactly one final newline, and SHALL NOT contain trailing whitespace on any line.

Line endings normalized

When
a document authored with mixed line endings is formatted
Then
the output uses the prescribed line ending throughout

Cross-platform round trip

Given
contributors on different operating systems
When
each formats the same document
Then
the results are byte-identical
