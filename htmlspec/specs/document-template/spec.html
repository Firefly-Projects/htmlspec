Core content is readable without JavaScript req-core-content-is-readable-without-javascript

Documents share one pinned runtime req-documents-share-one-pinned-runtime

Diagram, chart, and equation support SHALL come from a fixed set of approved libraries at versions pinned by the project. The runtime SHALL be shared across documents in a project rather than duplicated into each file. Arbitrary generated scripts SHALL NOT be embedded in a document.

Each runtime asset SHALL be stored at a location derived from the hash of its bytes. Identical bytes SHALL therefore occupy exactly one location in a project, and bytes that differ SHALL occupy distinct locations rather than overwriting one another. A document SHALL reference each asset by the hash it was authored against, so the bytes a document renders with cannot change without changing the document.

An asset location SHALL NOT be rewritten in place. Replacing a library SHALL add a location and leave existing locations intact, so a document authored earlier continues to render as authored.

A document declares its identity and provenance req-a-document-declares-its-identity-and-provenance

Every document SHALL declare, in machine-readable form, the schema version it conforms to, the change or spec it represents, and which artifact kind it is. A reviewer SHALL be able to see this information on the page without reading source.

The declared kind replaces the per-document lifecycle status. A stage — exploring, proposed, accepted, implementing, verified, archived — is a property of a change as it moves, not of each file in it: a proposal is a proposal for its whole life, and a specification does not become a proposal again. Declaring a stage per document therefore recorded the wrong thing about the wrong subject, and nothing in validation ever read it.

A document SHALL NOT declare a lifecycle status. Where a reviewer needs to know how far a change has progressed, the presence of its documents reports it: a change with a specification has been built, and a change with only a proposal has not.

The visual system favors comprehension over decoration req-the-visual-system-favors-comprehension-over-decoration

A document SHALL use the project's shared visual system: flat editorial layout, serif body text, high information density, and muted color. Color SHALL NOT be the only means of conveying meaning. Styling SHALL NOT hide or reorder semantic content.

Documents print cleanly req-documents-print-cleanly

A document SHALL provide print styling that produces a legible paper or PDF rendering. Navigation chrome and interactive controls SHALL be omitted from print output. Content SHALL NOT be truncated at page boundaries.

A project can be initialized with a conforming document req-a-project-can-be-initialized-with-a-conforming-document

The project SHALL provide a way to create a new document that already conforms to the element contract, the visual system, and the runtime conventions, without hand-assembly.

It SHALL also provide a way to create a new runbook without hand-assembly: a specification, a tasks document, a VERSION at 0.1.0, and a changelog heading for that version, where the project the working directory belongs to keeps its runbooks. The runbook SHALL validate at once, report ready with no machine checks, and start a run, and its documents SHALL take the subject a contributor gives, or the name where none is given. Its name SHALL be a plain directory name the project's layout leaves free: no path, no .., no character a terminal would not show as itself, no leading dot, and none of the names the layout already uses. A name refused, or a runbook that would not validate, SHALL leave nothing written.

Initialization SHALL write asset references that match the bytes it stores. It SHALL NOT copy a runtime asset that the project already stores, and SHALL NOT produce a document whose references and stored bytes disagree.

Initialization SHALL decide which project a new document belongs to from the location of the document it creates, never from the directory it runs in. A document created beneath a project's own directory, htmlspec/, SHALL reference that project's store, and establish it there if it is absent. Any other document SHALL be given a store beside it, because validation looks for a document's store in the document's own directory and above it, and the project's store is above only the documents beneath the project's own directory.

Whether a location is beneath a project's own directory SHALL be decided as the filesystem identifies that directory, whatever the location's spelling, and the store SHALL be referenced by the path the location spells.

A document stays readable when its stylesheet cannot load req-a-document-stays-readable-when-its-stylesheet-cannot-load

Every document the toolchain writes SHALL carry one fallback stylesheet in its head: a <style> element whose rules sit in the cascade layer htmlspec-fallback. The fallback SHALL set a property on a selector only where the stylesheet the document references sets the same property on the same selector, in a rule outside any cascade layer and any at-rule. So whenever that stylesheet loads, it overrides every declaration the fallback makes, and the page is the one it would be without the fallback.

The fallback SHALL reach nothing: it carries no url(, no @import, and no !important. It SHALL be the same text in every document a release writes, held once in the toolchain. Where the stylesheet cannot load, it SHALL leave the page readable: a centred column in the house serif and ink, monospace code, and a skip link that is hidden until it takes focus.

The fallback is neither the shared runtime that "Documents share one pinned runtime" governs, because it draws no diagram, chart, or equation and replaces nothing the store holds, nor a copy of a stored asset, which "A project can be initialized with a conforming document" forbids, because its bytes are no stored asset's bytes. A document without the fallback SHALL remain valid, and validation SHALL report nothing about a fallback that is absent or differs from the current text.
