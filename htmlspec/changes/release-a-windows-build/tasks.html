Status

Not scheduled. Every task is todo, and none is in progress.

1. Measure first

  • 1.1 Run the workspace tests on a Windows runner once, and record what fails task-1-1

    Dispatch a one-off job on windows-2025 running cargo test --workspace --locked, and record every failure as evidence. It decides how much of groups 2 and 3 there is.

2. The program on Windows

  • 2.1 Resolve a program on PATH through PATHEXT task-2-1

    Decision 4 of the design: try the bare name and each PATHEXT extension in each PATH directory, first match wins, and count a file as executable by its extension.

  • 2.2 Find the home and configuration directories through one lookup that knows Windows task-2-2

    Shared by preflight's home scope (preflight/host.rs:657) and the store registry (store.rs:25, registry_path), so a skill in the home scope and htmlspec store both work on Windows. Settle open question 7 of the design, %APPDATA% or USERPROFILE for the registry, before writing it.

  • 2.3 Refuse the toolchain check on Windows with an explanation task-2-3

    Name the platform and WSL, and keep the refusal distinct from a manager that is merely absent.

  • 2.4 Confirm cancellation and the deadline kill on Windows task-2-4

    Ctrl-C during a preflight, and a probe past its deadline that started a child of its own, each stop every process, through command-group's job object and signal-hook.

3. The tests on Windows

  • 3.1 Guard the four unguarded Unix uses in the integration tests task-3-1

    tests/run.rs:1042, :1164, :1173, and tests/archive.rs:2337, each with a Windows counterpart where the case still means something. Also a_failed_move_leaves_the_destination_unchanged in src/staging.rs (:1248), whose fallback lock at :1270 Windows ignores on a directory: make the move fail another way on Windows, or guard it and count it under task 3.3.

  • 3.2 Give the fake tools in the preflight tests a Windows form task-3-2

    Write a .cmd script on Windows where the helper writes #!/bin/sh now. Four more tests run a real program through real_executable (preflight/host.rs:1839): sleep at :1729 and :1765, sh at :2614, and git at :2709. Give each a Windows program that behaves the same, or guard it and count it under task 3.3. The process-group test at :1799 stays Unix-only, as decision 5 says.

  • 3.3 Record which tests do not run on Windows, and why task-3-3

    Count the remaining #[cfg(unix)] tests in the evidence, so the coverage gap is stated. Seven whole tests are guarded today: commands.rs:10005; project.rs:898, :959, :989, and :1086; topology.rs:175; and preflight/host.rs:2403.

4. Line endings

  • 4.1 Add a .gitattributes that keeps every asset store byte-exact task-4-1

    Decision 6: no line-ending conversion under **/assets/sha256-*/**, and documents kept at LF.

  • 4.2 Decide, then implement or drop, init writing the store rule for a project task-4-2

    Open question 3 of the design. Settle it with the contributor before writing code.

5. The release

  • 5.1 Add the Windows target to the release facts, gated like the macOS targets task-5-1

    TARGETS, RUNNERS, a Windows set gated by the public repository or release-check, and five entries in the BuildMatrix tests.

  • 5.2 Link the C runtime statically for the Windows target task-5-2

    In .cargo/config.toml, for x86_64-pc-windows-msvc alone.

  • 5.3 Pack a reproducible zip and list it in SHA256SUMS task-5-3

    Decision 2, with a test that packing twice gives one digest.

  • 5.4 Have the formula read only the Homebrew targets, and the release job accept the zip task-5-4

    scripts/render-formula and the release job's per-target check.

  • 5.5 Run the workspace tests on Windows in CI, gated task-5-5

    Decision 7: a workflow of its own, .github/workflows/windows.yml, with the labeled trigger, the gate release.yml computes for its macOS jobs, and a header stating its exception to toolchain-packaging's "Project checks are runnable as one command". Not a job in check.yml.

  • 5.6 Make the release build job run on a Windows runner task-5-6

    In .github/workflows/release.yml's build job: its steps use bash syntax (set -euo pipefail, $(...), case) while a Windows runner defaults to PowerShell, so set shell: bash for the job; the binary path target/$TARGET/release/htmlspec lacks .exe in the run step and the pack step; and the upload pattern dist/*.tar.gz misses the zip.
