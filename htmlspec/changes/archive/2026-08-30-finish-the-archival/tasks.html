4. Archival performs the archival

  • 4.1 Split the existing archive_check into the gate it already is and the operation that follows, so the refusing conditions keep their current messages and exit codes unchanged

  • 4.2 Add the task count, reading the change's tasks document.

    Report the count and offer to proceed

  • 4.3 Add the merge assessment: collect requirement identifiers from the change's specification.html, collect them from the accepted specifications, report identifiers present in the first and absent from the second.

    Name them individually — a count is not checkable in under a minute and a list of three identifiers is

  • 4.4 Add the move: target <YYYY-MM-DD>-<name>, no second date where the name already carries one, refuse on collision naming the existing archive, and rename rather than copy

  • 4.5 Write the VERSION file recording the declared version.

    Where the write fails after the rename, report the archive location and the failed write together — the change is archived and one file is missing, and reporting that as a failed archival sends a contributor to redo something that already happened

  • 4.6 Add --yes and the interactive prompt, with no prompt where the stream is not interactive

  • 4.7 Extend the --json payload with the reports and a field stating whether the change moved

  • 4.8 Assert atomicity in both directions: a refused archival and a declined offer each leave the tree byte-identical, compared before and after

    Migration note: a refused archival is asserted by comparing the whole tree before and after (a_refused_archival_leaves_the_project_untouched), and so is a warned run that nothing can answer (findings_with_no_one_to_ask_stop_the_archival). A declined offer is asserted another way: a_declined_offer_stops checks that the consent decision returns a stop, and no test compares the tree after a declined offer. Shown in crates/htmlspec-cli/tests/archive.rs and crates/htmlspec-cli/src/commands.rs at cf11132.

  • 4.9 Assert the_archive_check_does_not_write_the_declaration still passes unchanged.

    Archival now writes to the project and still must not touch spec.nix, which is exactly the obligation the withdrawal was careful to preserve

    Migration note: the test was changed to keep passing. Its successful archival now passes --yes, because archival performs and the test's change carries findings that would otherwise stop it. Its assertions that the declaration is unchanged are as they were. Shown in crates/htmlspec-cli/tests/archive.rs at cf11132, against its parent.

  • 4.11 Add --check, applying every condition archival applies and performing none of them.

    It shares the gate with archival rather than reimplementing it — two code paths deciding readiness is exactly the drift the requirement exists to prevent

  • 4.12 Assert --check three ways: ready exits zero and reports ready, refused exits nonzero with archival's own message, and would-ask exits zero while saying archival would ask.

    Assert in all three that the tree is byte-identical before and after

    Migration note: of the three ways, the would-ask case is asserted, the refused case only in part, and the ready case not at all. check_mode_reports_readiness_without_archiving asserts "ready with questions", because its fixture always carries a finding, and no test asserts that a ready change exits zero and reports ready. check_mode_fails_where_archival_refuses asserts a nonzero exit and does not compare the message with archival's. Both compare the tree before and after. Shown in crates/htmlspec-cli/tests/archive.rs at cf11132.
