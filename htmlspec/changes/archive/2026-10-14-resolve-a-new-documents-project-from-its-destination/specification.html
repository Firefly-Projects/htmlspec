Resolve a new document's project from its destination

This change makes document-template's "A project can be initialized with a conforming document" say which store a new document references: the store its own location reaches, never the one the directory the command runs in reaches. A document beneath a project's own directory references the project's store, and any other document is given a store beside it.

document-template

A project can be initialized with a conforming document req-a-project-can-be-initialized-with-a-conforming-document

The project SHALL provide a way to create a new document that already conforms to the element contract, the visual system, and the runtime conventions, without hand-assembly.

Initialization SHALL write asset references that match the bytes it stores. It SHALL NOT copy a runtime asset that the project already stores, and SHALL NOT produce a document whose references and stored bytes disagree.

Initialization SHALL decide which project a new document belongs to from the location of the document it creates, never from the directory it runs in. A document created beneath a project's own directory, htmlspec/, SHALL reference that project's store, and establish it there if it is absent. Any other document SHALL be given a store beside it, because validation looks for a document's store in the document's own directory and above it, and the project's store is above only the documents beneath the project's own directory.

Whether a location is beneath a project's own directory SHALL be decided as the filesystem identifies that directory, whatever the location's spelling, and the store SHALL be referenced by the path the location spells.

Evidence

Each unit summarizes a record this change carries in its evidence/, and links it. The record is the authority.

The four cases, measured before the change evidence-the-four-cases-measured-2026-10-13

With htmlspec 0.29.0 in a scratch project, three of the four arrangements of working directory and destination went wrong: written outside the project from inside it, and into its root from inside it, new document exited 2 with a document validation rejected; written into its htmlspec/ from outside, the project gained a second store that htmlspec assets reported. Written outside every project, it was correct. evidence/the-four-cases-measured-2026-10-13.md

The tests, before the repair and after it evidence-the-tests-before-and-after-2026-10-13

Before the repair, five of the tests failed, the four arrangements' three failures, the project with no store, and the test that failed when this repository became a project; after it, every one passed. It also records a document in a project's root, referencing htmlspec/assets/, accepted by validation with a stylesheet hash that names no stored bytes. evidence/the-tests-before-and-after-2026-10-13.md

The tests can fail evidence-mutation-testing-2026-10-13

With the working directory put back as the project's source, seven tests failed and the three that cover what must not move passed. With the code review's comparison by spelling put back, both tests for a directory named another way failed, and the review's own case ran end to end on a filesystem that ignores case. evidence/mutation-testing-2026-10-13.md

The check suite, with the promoted project in place evidence-the-check-suite-2026-10-13

Every stage of scripts/check that runs Rust passed inside nix develop. The four Python stages failed there only on macOS's python3 shim, and passed outside it, after the 45 installed instruction files were regenerated for 0.29.1. evidence/the-check-suite-2026-10-13.md
