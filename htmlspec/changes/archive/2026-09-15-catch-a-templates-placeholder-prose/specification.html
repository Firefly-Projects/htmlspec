It confined the rule that checks an example's identifier rather than its text to units, and required that a summary be checked on its text, compared whole, against placeholder text derived from the templates, and that an absent summary not be reported as example content.

contract-authority

Generated example content is non-normative and its survival is reported req-generated-example-content-is-non-normative-and-its-survival-is-reported

A template's example content SHALL carry no authority. An example requirement writes no obligation, an example scenario states no behavior, and an example task enumerates no work, and a template's placeholder summary states nothing about what a document is for.

Validation SHALL report a document carrying a unit whose identifier is one a template writes as an example. Validation SHALL also report a document whose summary is text a template writes as a placeholder. Every operation that puts a change's contract into the accepted specifications SHALL refuse while that change's specification carries oneeither. Archival is one such operation and SHALL refuse. So SHALL any other, including one that reports the merge for an agent to perform rather than performing it itself.

Stated as a property of the operation rather than as a list of commands, because a list goes stale the way a count does. The comparison operation is the case that proves it: it never edits an accepted specification, so a rule naming only archival leaves it uncovered — and its report names each requirement no accepted specification holds and directs an agent to merge it. On a specification straight from a template that direction reads "merge the example requirement", which is the obligation nobody wrote entering the contract by the hand of an agent doing as it was told.

The two SHALL differ in severity, and the reason is where each fires. A document carries example content the moment it is created, because creation writes a template and the result is required to be valid, so an error at that moment would report a defect the program itself introduced. Example content reaching an operation that applies a contract is an obligation nobody wrote entering the accepted specifications, which is what the refusal exists to prevent.

The identifiersBoth the identifiers and the placeholder text SHALL be derived from the templates rather than listed separately. A list beside the templates states the same fact twice and goes stale the first time a template gains a unit or rewords a placeholder.

The checkWithin a unit, the check SHALL be on the identifier rather than on the example's text. Text is edited while an identifier survives, so a half-replaced example carries new prose under the example's identifier — and that is the likely case rather than an edge one.

A document's summary SHALL be checked on its text, because it has no identifier to survive. The summary projects from the paragraphs of the document header, which carry no identifier of their own, so the rule about units does not narrow to this case — it does not reach it at all. That is a measured gap rather than a hypothetical one: a document whose entire summary read "Replace this paragraph with what this work delivers." was reported as carrying no diagnostics, and a person found it by opening the file.

The comparison SHALL be against the whole projected summary rather than against a fragment of it. A summary an author has written SHALL NOT be reported for quoting a template's wording inside a longer statement, because an author explaining the placeholder is not carrying it. What is reported is a summary that is the placeholder and nothing else.

Where a document's summary is absent, that SHALL be reported by whatever rule governs an absent summary and SHALL NOT be reported as example content. An absent summary and a placeholder summary are different facts about a document, and a rule reporting one as the other would send an author to delete a paragraph that is not there.

Migration note: the proposal argues for the refusal at archival from the permanent record, into which a change archived with a placeholder summary would put "Replace this paragraph". The refusal as built reads only the change's specification, as this requirement states it: example_content_in (crates/htmlspec-cli/src/commands.rs at 0ce5ad5) collects the specification's example identifiers and compares its summary, and nothing else, so a placeholder summary in a change's proposal, design, tasks, or evidence does not stop archival. The instance that motivated the change was an evidence document, which evidence/the-gap-measured-2026-09-13.md records archival's existing refusal could not reach.
