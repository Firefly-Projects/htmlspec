    • Taken: a change element that is itself a unit passed. <del class="decision" …> in a design was accepted with no diagnostics, because the rule asked only the element's ancestors and descendants, and the projection makes the element a unit. Covered by two tests and mutation N1

    • Taken: the ins reason was wrong beside a del. It said a reader cannot see what the inserted words replaced, which is false in the spec's own headline case. It now says the projection keeps the inserted words as ordinary text, so the edit the page shows is in no field the model holds. Covered by each_change_element_gives_its_own_reason

    • Taken: markup in one unit around another named no fix for the unit it wraps. It is still located at the enclosing unit, as design decision 3 states, and its fix is now the wrapped unit's change state. Covered by markup_in_a_unit_around_another_names_the_unit_it_wraps

    • Taken: SVG and MathML elements named del or ins were reported. Only HTML-namespace elements are change markup now

    • Taken: five wrong implementations survived the tests: enclosed before enclosing, direct children only, case-insensitive classes, swapped reasons, and quoting split on spaces. Each now has a test that catches it, and the ten original mutations are still caught. evidence/mutation-testing-2026-10-01.md

    • Taken: three statements of the version policy still said a minor bump invalidates no document, in CONTRACT_VERSION's comment, the schema's schemaVersion description, and the contract changelog. Each now gives the reason that still holds. The changelog's fix wording, which still ordered modified for every unit, now matches the message. Both changelogs' "no tracked file carries the markup" now says "before this release", because the two new fixtures carry it

    • Taken: the hand-authored table checked only input.html. It now checks expected.json too

    • Not taken: the policy table's Minor row. It states what a minor bump means once the vocabulary is committed, and the 0.x clause directly below it covers this release

    • Not taken: <del><ins><section class="requirement"> draws two fixes, removed and added, at one unit. Each element is its own edit, and the two contradict because the document does. One diagnostic per element is design decision 3

    • Not taken: a task wrapped in del is told data-change="removed" and not data-state="dropped". The two say different things. removed withdraws the task from what the change states, and dropped records work that was planned and not done, with a reason. The markup cannot say which the author meant, and both validate
