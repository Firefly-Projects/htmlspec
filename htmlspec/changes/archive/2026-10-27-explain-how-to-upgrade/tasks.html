Group 1 is the work. Group 2 reviews it, archives it, and rehearses the export of what archival leaves. Every task is in one pull request.

1. The guide

  • 1.1 Write the README's Upgrading section task-1-1

    Add ## Upgrading after "Getting started", and link it from "After installing". It covers the binary on each channel and the project, as design decisions 2 and 3 give them, what 1.x promises, as decision 4 gives it, and a short list of what each release from 1.1 on lets a project adopt. Run each command, or read it from its own help, before writing it, never against the real home directory or the real Nix profile.

    Done on 2026-10-27, with more than the task's words. Besides the binary, the project, what 1.x promises, and what each release lets a project adopt, the section gives the one grep line that shows which release a project's instructions come from, and says init also refreshes its marked region of AGENTS.md. The upgrade commands were read from their own help on this machine (brew upgrade --help, cargo install --help, nix profile upgrade --help, nix flake update --help) and not run, because each would upgrade this machine. The project steps were run in a scratch project made by 1.1.0 and brought up with 1.2.0: init changed only the instruction files, format --upgrade-assets had nothing to move, and validate reported 0 errors.

  • 1.2 Add an upgrading note to each changelog entry from 1.1.0 on task-1-2

    1.1.0, 1.1.1, and 1.2.0 each gain a short "Upgrading" paragraph, as decision 5 gives them. Add the ## 1.2.1 entry for this change, with its own note.

    Done on 2026-10-27. The notes sit at the end of the 1.1.0, 1.1.1, and 1.2.0 entries, under an ### Upgrading heading, and the new 1.2.1 entry has its own.

  • 1.3 Check the README's upgrade blocks as its install blocks are checked task-1-3

    Mark each upgrade block with <!-- upgrade: NAME -->. Teach scripts/check-readme-install the marker, require upgrade-homebrew, upgrade-cargo, upgrade-nix, and upgrade-project, and parse each with bash -n. Add self-test cases for a missing upgrade block and an unparseable one, and see each fail against the old script.

    Done on 2026-10-27. scripts/check-readme-install reads upgrade: markers beside install: ones, sharing one set of names, requires the four upgrade blocks, refuses one marked as an install block, and parses each with bash -n. Five self-test cases were added, 16 in all, and the review's fixes added three more, 19 in all: an install block marked upgrade:, and --print printing an install block and refusing an upgrade block. Main's script passes a README whose upgrade-nix marker is removed and whose upgrade-homebrew block does not parse. This one refuses it, naming both.

  • 1.4 Advance the release to 1.2.1 task-1-4

    Run scripts/set-version 1.2.1, which moves the pins, the lockfile, and the installed instructions' generatedBy lines. spec.nix moves at archival.

    Done on 2026-10-27, by another route for one part. scripts/set-version 1.2.1 moved the version, the five pins, and the lockfile, but not the installed instructions' generatedBy lines. Those were regenerated by the 1.2.1 binary's own htmlspec init --tools claude,codex,pi, which changed nothing else, and scripts/check-installed reports the 45 files match.

2. Review, archive, and rehearse

  • 2.1 Take the code review, and settle each finding task-2-1

    One review, read-only, of the pull request. Settle each finding on the branch before archiving.

    Done on 2026-10-27. One read-only review of pull request 91 found the commands correct and raised documentation findings, each settled on the branch in commit 1519a1c: an upgrade from 1.1.x is cumulative, because 1.1.1 and 1.2.0 were not published on their own, and 1.2.1's note and the README now say so; the command naming which release wrote a project's instructions also reads AGENTS.md; the document promise carries its exception and is stated about the contract's version; the Nix tag, version, and nix run caveats; init writing missing assets; the reconstructed notes headed added in 1.2.1; the promises stated once and linked; records read both ways set apart as observed; the design's measurement of init corrected; --print refusing an upgrade block and the script's messages; and the macOS, Homebrew-on-Linux, and adoption-list wording.

  • 2.2 Archive at 1.2.1 task-2-2

    Write the specification from what was built, restating toolchain-packaging's "A release reaches every channel from one tag" whole as Modified. Move spec.nix to 1.2.1, and archive with htmlspec archive explain-how-to-upgrade.

    Done on 2026-10-27. The specification restates toolchain-packaging's "A release reaches every channel from one tag" whole, as modified: its seventh statement gains the upgrade blocks, with the words marked, and one scenario, "An upgrade block missing or mismarked", is added. show --diff reported the words marked as the author marked them, and sync reported the contract applied in full. spec.nix is 1.2.1. Archived with --yes while task 2.3, which follows archival, was still open.

    Done on 2026-10-27, after archival. The ten allowlisted paths this change touched were read at the content archival leaves, and their rows recorded in publish/READINESS.md with one read paragraph: 912 added lines swept, with no private hit. publish/export --ref HEAD --dry-run then ran against an empty local bare repository, and its result is recorded in the pull request.
