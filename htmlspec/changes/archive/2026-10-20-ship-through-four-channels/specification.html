toolchain-packaging

A release reaches every channel from one tag req-a-release-reaches-every-channel-from-one-tag

Every release SHALL be cut from one tag, vX.Y.Z, whose version equals the version the workspace declares, and the binaries, the crates, and the Homebrew formula the release produces SHALL each name that version. The release SHALL refuse a tag that names another version before it builds anything.

Publication SHALL begin only from a version tag in the public repository, Firefly-Projects/htmlspec, only for a commit that repository's main holds, and only after the check suite has passed on that commit. A tag in any other repository SHALL publish nothing.

A publication interrupted partway SHALL finish when run again, and SHALL NOT publish any version twice: the crates publish one at a time, a version the registry already holds is skipped, and a rate limit is waited out within a stated budget, after which the run stops and names the crates that remain. Every request the release makes to crates.io SHALL carry a fixed User-Agent that names the project, and no personal information.

The formula matches the release verify-the-formula-matches-the-release

In runs 39353659674 and 39355492345, the formula job rendered the formula from the run's own SHA256SUMS with scripts/render-formula, placed it in a tap made with brew tap-new --no-git, and passed brew audit --strict, brew install, and brew test. Run locally, the renderer refuses a SHA256SUMS lacking a target, naming two versions, or naming a file that is not a release tarball, and a template whose license or targets drift from the crate.
