Each task is one unit of work, individually addressable, so a state change is a change to one unit rather than to a list.

  • 1.1 Name each runbook the upgrade rewrites, and what its version needs task-1-1

    In format (crates/htmlspec-cli/src/commands.rs), collect each runbook whose specification.html or tasks.html the upgrade rewrote, or checking would rewrite, judged where the document resolves. After the walk, report one line per runbook in name order, reading its VERSION and the published history as decision 2 says, with the name escaped. Tests in tests/runbooks.rs: a runbook released at its current version is named as needing a greater one, in both modes, and archive --check refuses it; a runbook at an unreleased version is named as releasing at that version, and archival publishes it; a run's record, a document outside a runbook, and an upgrade that moved nothing add no line.

    Done on 2026-10-28, with more than the task's words. The decision is its own pure function, runbook_release::version_after_a_change, beside compare_release, and a unit test holds the two to the same answer for changed content in five cases. Writing it showed two cases the design's first list missed, a runbook at 0.0.0 and one below a published version, which archival also refuses, so each has its own line and the design names four outcomes. The three tests are in tests/runbooks.rs. The two that expect a line fail against 1.2.1's sources and pass with the change; the third, which names nothing for a run's record, a document outside every runbook, or a runbook already on the current assets, passes on both, as a guard.

    Done on 2026-10-28. The unit test changed_content_without_a_bump_is_refused_naming_the_archive holds the sentence, and the integration test for a released runbook checks that archive --check's refusal carries it.

  • 1.3 Name each runbook the fallback rewrites, as the upgrade does task-1-3

    Asked for after the pull request opened. format --fallback rewrites runbook documents the same way, so it gives the same line in both modes. Archival's refusal names --fallback beside --upgrade-assets. The option's help, the README, and the design say the same. A test shows a released runbook given the fallback is named, and that the line is absent when nothing changes. It stays a patch, with no new surface.

    Done on 2026-10-28. A runbook is recorded once a document's requests have all succeeded, with what was rewritten as one of three values, the assets, the fallback, or both, which the line for an unreleased version uses to say what its heading says moved. Two tests in tests/runbooks.rs: a released runbook given the fallback is named in both modes and refused by archival, whose refusal names --fallback, while a runbook already carrying the fallback and a second request name none; and an unreleased runbook's advice says the fallback alone, then both requests, changed it. Both fail against the pull request's first head and pass now. The unit test for the refusal checks it names both options.

  • 3.1 Take the review, and settle each finding task-3-1

    One review of the pull request, as the merge rule requires. Each finding is fixed or answered on the pull request before archival.

    Done on 2026-10-28. Before the review the coordinator asked for --fallback too, which is task 1.3. One review of pull request 93 then raised seven findings, each reproduced first by a test that failed at b980f52 and settled in b4d4bc7. A runbook was named for a document the formatter refused or could not write: it is now recorded once the formatter accepts the document, when checking, or once it is written, when writing. Any HTML file in a runbook's directory named the runbook, and a runbook directory that is a link went unnamed: a runbook is now a directory runbook_release::present lists, named as it lists it, each directory resolved, and only its specification.html and tasks.html name it. The "not released yet" line promised a release without the changelog heading archival requires: version_after_a_change reads the changelog and asks for a missing heading. Names reached the terminal through the listing's rendering: the new lines, every document path in format's report, and the name, directory, and archive in archival's release faults now go through terminal::shown, with an escape-sequence test. Among the nits, the long doc comment is wrapped, the published history is read once per project, the changelog title names both options and the entry describes the 0.0.0 line, and a never-published runbook is no longer told what its first heading says. The optional finding was a one-sentence change, so archival's refusal also names a reference plain formatting filled, and the design records the fill as an accepted risk.
