Read a document whose stylesheet cannot load

Every document reaches its stylesheet in the project's one asset store, in a folder above the document. Safari, opening a document from disk, refuses a stylesheet in a parent folder, so there every document renders as bare HTML. This change gives every new document a small inline fallback stylesheet that changes nothing while the real stylesheet loads and keeps the page readable when it does not. The vocabulary of the contract does not change.

Subject
Read a document whose stylesheet cannot load

Why

A reader opened a runbook in Safari, saw plain HTML, and took it for a runbook missing the styling the specifications have. The styling is the same. The cause is where the stylesheet sits.

Measured on 2026-10-15, with a page that loads four stylesheets from four places and colours one line for each that loads: Safari, opening the page from disk, loaded the stylesheet beside the page and the one in a subfolder, and refused the one a folder up and the one two folders up. Chrome 154 and Firefox 158 loaded all four. An html-spec document always reaches the project's store above it: an accepted specification at ../assets/, a change or a runbook at ../../assets/, an archived change or a run's record at ../../../assets/. So in Safari, from disk, no document gets its stylesheet. A specification opened there runs edge to edge in the browser's default font, with its masthead fields stacked as a bare definition list.

The documents are not at fault. document-template's "A document is self-contained and offline" holds: every reference resolves within the project and nothing reaches the network. What is missing is a page that stays readable when the browser refuses the reference.

What working looks like

  1. htmlspec new document and htmlspec new change write documents whose head carries one <style> element holding a cascade layer named htmlspec-fallback, and the documents validate immediately, as before.
  2. Opened with the store reachable, a document with the block renders exactly as the same document without it. Measured as two screenshots that are identical byte for byte.
  3. Opened with the store unreachable, which is Safari opening a document from disk, the document renders as a readable centred serif column, with code in a monospace face and the skip link hidden until a keyboard user reaches it.
  4. A test fails when the block sets a property that the store's stylesheet does not also set, unlayered, on the same selector, when the store's stylesheet gains a cascade layer, or when the block references anything.
  5. htmlspec format --fallback <path> adds the block to the documents a project already holds and refreshes one that differs from the current block. Plain htmlspec format never adds it. Neither touches an archived change or a run's record.
  6. A run's record carries the block, as a document the program writes.
  7. document-template states the block as a requirement: what it is, why it is inert, and why it is neither the shared runtime nor a copy of a stored asset.
  8. This repository's 13 accepted specifications carry the block.
  9. This is release 0.31.0, and scripts/check passes.

What changes

The toolchain holds one fallback stylesheet. It is a few hundred bytes of CSS in a named cascade layer. A declaration in a named layer loses to every declaration outside a layer, whatever their order, and the store's stylesheet declares nothing in a layer. The fallback sets only properties that the store's stylesheet also sets on the same selectors, so whenever the store's stylesheet loads, every property the fallback sets is overridden. When it does not load, the fallback is all there is: a centred column, the house serif and ink, monospace code, and a hidden skip link.

Every document the program writes carries it. The four templates hold one placeholder for it, so new document and new change write it, and the run record's head writes it too. The text lives in one place in the asset crate.

Existing documents gain it only when a contributor asks. htmlspec format --fallback adds it, or replaces a block that differs from the current one, and does nothing else. Plain formatting leaves a document's fallback present, absent, or stale as it was. Archived changes and run records are history, and the request leaves them as written.

The contract states it. document-template gains the obligation. deterministic-formatting's "Formatting preserves meaning", which today permits one exception, filling an asset reference that names absent bytes, gains a second: the fallback, on request.

Alternatives considered

A command that serves the project over local HTTP. Safari loads a stylesheet from a parent path over HTTP. Rejected as the fix, because the reader who double-clicks a file still gets bare HTML, and a document should not depend on how it was opened. It remains a reasonable later convenience.

A single-file export. htmlspec export would write a self-contained copy with the runtime inlined, which also makes diagrams portable. Set aside for now at the contributor's choice: it is larger, and it answers sharing a copy, not reading the document in place.

Inline documents chosen at init, with a convert command. Rejected. Inlining the runtime costs about 72.7 MB across this repository, against 6.35 MB in the one store, and it contradicts document-template twice: "Documents share one pinned runtime" shares the runtime across documents "rather than duplicated into each file", and "A project can be initialized with a conforming document" forbids copying a runtime asset the project already stores. Two document forms would also make every tool handle both.

The formatter adds the block to every document. Rejected. A runbook's release is fingerprinted by the hash of its canonical document, so a formatter that added the block would change every runbook's fingerprint on upgrade and refuse every project's next archival until each runbook raised its version, for no change to any procedure. It would also rewrite every archived document, which the reference-filling rule already refuses to do for the same reason: an archived page renders with what it was reviewed against.

Fingerprints that leave the block out. Rejected. It makes a runbook's canonical bytes and its fingerprint mean two different things, and it hides a real edit to the document from the release check.

The full stylesheet inlined as the fallback. Rejected. It is 28 KB per document, it is a copy of a stored asset's bytes, which document-template forbids, and it would have to change in every document whenever the stylesheet changed.

Scope

In scope. The fallback block and its single home in the asset crate. The four templates and the run record's head. htmlspec format --fallback. A test that holds the block inert against the store's stylesheet. The two requirements. This repository's accepted specifications, and this change's own documents.

Diagrams and scripts are out of scope. The fallback restores a readable page, not the design: it carries no contents column and no unit styling, and it draws no diagram. Mermaid and Vega-Lite still load from the store, so a reader in Safari sees each figure's source in its <details> element, as document-template's "Core content is readable without JavaScript" already provides. Whether Safari also refuses scripts from a parent folder was not measured.

No validation diagnostic. Validation says nothing about a missing or stale block. Every document written before 0.31.0 lacks it legitimately, and the block is presentation, not content.

Not touched. Archived changes, which are history. The release runbook, whose canonical documents would change and require a runbook release, 0.3.0, with no change to any step. It gains the block at its next revision. No export, no inline setting at init, and no convert command.

The README. Its "Reading the documents" section, added by pull request #61, tells Safari readers to serve the project. #61 landed first, so this change rewrites that section: a document the program writes stays readable in Safari, diagrams and charts still need the store's scripts, and htmlspec format --fallback gives older documents the fallback.

Requirements. One added to document-template, and deterministic-formatting's "Formatting preserves meaning" modified. The contract's vocabulary does not change: an inline <style> element in a document's head is already accepted, and the projection does not read it.

The release. The size of an increment is judgment, and the choice is mine: a minor, 0.31.0, because every document the program writes now carries something it did not, and format gains a request.
