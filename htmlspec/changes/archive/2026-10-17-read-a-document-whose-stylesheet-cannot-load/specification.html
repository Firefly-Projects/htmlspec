Read a document whose stylesheet cannot load

What this change established. Every document the toolchain writes carries a fallback stylesheet that keeps the page readable where the store's stylesheet cannot load, as in Safari opening a document from disk, and that changes nothing where it loads. Existing documents gain it only on request, through htmlspec format --fallback. Release 0.31.0, with the contract at 0.7.0.

document-template

A document stays readable when its stylesheet cannot load req-a-document-stays-readable-when-its-stylesheet-cannot-load

Every document the toolchain writes SHALL carry one fallback stylesheet in its head: a <style> element whose rules sit in the cascade layer htmlspec-fallback. The fallback SHALL set a property on a selector only where the stylesheet the document references sets the same property on the same selector, in a rule outside any cascade layer and any at-rule. So whenever that stylesheet loads, it overrides every declaration the fallback makes, and the page is the one it would be without the fallback.

The fallback SHALL reach nothing: it carries no url(, no @import, and no !important. It SHALL be the same text in every document a release writes, held once in the toolchain. Where the stylesheet cannot load, it SHALL leave the page readable: a centred column in the house serif and ink, monospace code, and a skip link that is hidden until it takes focus.

The fallback is neither the shared runtime that "Documents share one pinned runtime" governs, because it draws no diagram, chart, or equation and replaces nothing the store holds, nor a copy of a stored asset, which "A project can be initialized with a conforming document" forbids, because its bytes are no stored asset's bytes. A document without the fallback SHALL remain valid, and validation SHALL report nothing about a fallback that is absent or differs from the current text.

deterministic-formatting

Formatting preserves meaning req-formatting-preserves-meaning

Formatting SHALL NOT change a document's semantic content. It SHALL preserve every semantic unit, every identifier, every attribute value, every cross-reference, and the document order of content. It SHALL NOT add, remove, or reorder semantic units.

One kind of attribute value is excepted. Where an asset reference names bytes the project's store does not hold, formatting SHALL fill it with the address of the bytes the toolchain ships. A reference that names bytes the store holds SHALL be left as written, even when the store also holds a newer revision, because the reference records what the document was authored against.

An asset reference SHALL be the value of an attribute through which an element loads an asset. These are the same attributes that document-validation's "An asset reference must match the bytes it names" judges, so the formatter and the validator SHALL NOT disagree about which values are references. A hyperlink is a citation, not something the document loads, and SHALL NOT be filled. Text SHALL NOT be read as an asset reference. Prose that quotes one, whether as characters in a code element or escaped in an example, is content, and formatting SHALL leave it as the author wrote it.

A second exception is made only on a contributor's request. Where the request is made, formatting SHALL add the fallback stylesheet that "A document stays readable when its stylesheet cannot load" describes to a document that lacks one, SHALL replace a fallback whose text differs from the current one, and SHALL change nothing else. It SHALL NOT do so for a document of an archived change or a run's record, which are history, whether reached directly or through a symbolic link. Without the request, formatting SHALL leave a document's fallback present, absent, or stale as written.

Evidence

What was measured before the change evidence-the-measurement-2026-10-16

Safari refuses a stylesheet one and two folders up from a page opened from disk, and Chrome and Firefox load it. Every kind of document reaches the store in a parent folder. The store's stylesheet sets every property the fallback sets on its selectors, unconditionally and with no layer, and a document carrying the block validates with the same diagnostics as one without it. evidence/the-measurement-2026-10-16.md

The renders with and without the store evidence-the-renders-2026-10-16

Rendered by Chrome headless with the store reachable, the runbook-portability specification with the fallback and without it gave identical screenshots. With the store unreachable, the fallback gave a centred serif column with monospace code, and the copy without it rendered edge to edge in the browser's defaults. evidence/the-renders-2026-10-16.md

Verification

The fallback is inert against the store's stylesheet verify-the-fallback-is-inert

crates/htmlspec-assets/tests/fallback.rs parses the fallback and the embedded store stylesheet. the_fallback_is_inert_against_the_store_stylesheet requires every property on every fallback selector to be set by an unconditional, unlayered store rule naming the same selector. the_store_stylesheet_declares_no_cascade_layer and the_fallback_is_one_layer_that_reaches_nothing hold the layer and the absence of url(, @import, and !important. Four more hold the checker to crafted failures. With text-align: left added to the fallback's body, the first test failed naming that property, and passed once it was removed.

The skip link returns on focus verify-the-skip-link-returns-on-focus

the_fallback_brings_the_skip_link_back_on_focus failed against the block before the code review's fix and passes now. the_skip_link_check_reports_a_link_hidden_for_good holds the check itself.

Every document the toolchain writes carries the fallback verify-every-writer-carries-the-fallback

every_rendered_template_carries_the_fallback_once_in_its_head in crates/htmlspec-validate/tests/template_conformance.rs renders every kind's template, and the_rendered_template_is_already_canonical now covers every kind. the_record_carries_the_fallback_stylesheet_once in crates/htmlspec-cli/tests/run.rs starts a run and reads the fallback once in the record's head, and the record passes strict validation and format --check. It failed against the record's previous head.

Formatting adds the fallback only on request verify-format-adds-the-fallback-only-on-request

In crates/htmlspec-cli/tests/cli.rs: plain_format_leaves_a_document_without_the_fallback_without_one, format_fallback_adds_it_once_and_is_then_idempotent, format_check_fallback_reports_a_document_without_it_and_writes_nothing, a_stale_fallback_is_replaced_only_on_request, format_fallback_leaves_history_as_written, and put_format_takes_the_fallback_request. In crates/htmlspec-format/src/fallback.rs, seven unit tests hold the transformation, among them that a stale fallback is replaced and nothing else moves. a_document_reached_through_a_symbolic_link_into_history_is_history in crates/htmlspec-cli/src/project.rs failed before the code review's fix and passes now.

This repository's accepted specifications carry the fallback verify-the-repository-carries-it
