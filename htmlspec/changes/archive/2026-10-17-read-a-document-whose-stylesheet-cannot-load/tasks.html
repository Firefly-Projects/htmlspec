2. The fallback

  • 2.1 Hold the fallback once, in the asset crate. task-2-1

    One constant holding the whole <style> element in its canonical form, with the store's values and the centred column (design decision 2, and "The mechanism").

    htmlspec_assets::fallback::ELEMENT in crates/htmlspec-assets/src/fallback.rs, with css() for its text and is_fallback_text, which recognizes a fallback, current or stale, by its @layer htmlspec-fallback opening. The values are the store stylesheet's own, resolved from its custom properties, except the body's padding, which centres a column of at most 44rem. The element was 735 bytes, and is 794 since the code review added the skip link's focus rule (6.1).

  • 2.2 Test that the fallback is inert against the store's stylesheet. task-2-2

    Every property on every selector is set by an unconditional, unlayered store rule naming the same selector. The store declares no layer. The fallback is one @layer htmlspec-fallback block with no url(, @import, or !important (design decision 1). See the test fail with a property the store does not set, and pass without it.

    Seven tests in crates/htmlspec-assets/tests/fallback.rs. Three hold the real texts: the_fallback_is_inert_against_the_store_stylesheet, the_store_stylesheet_declares_no_cascade_layer, and the_fallback_is_one_layer_that_reaches_nothing. Four hold the checker to crafted inputs: a property the store does not set, a selector the store does not name, a store rule inside @media, and a rule outside the layer, !important, or url(. With text-align: left added to the fallback's body, the first test failed naming ("body", "text-align"). Restored, all seven pass.

  • 2.3 Write the fallback into every template. task-2-3

    {{FALLBACK}} on its own line after the title in each of the four templates, substituted by render_kind. Update the templates' hashes in assets/vendor.lock.json. Extend the_rendered_template_is_already_canonical to every kind, and test that each rendered template carries the fallback exactly once.

    Each of assets/template-*.html holds {{FALLBACK}} on the line after its title, and render_kind substitutes htmlspec_assets::FALLBACK_PLACEHOLDER with the element. The four templates' hashes in assets/vendor.lock.json were re-pinned, and nothing else recorded the old ones. the_rendered_template_is_already_canonical now renders every kind, and every_rendered_template_carries_the_fallback_once_in_its_head is new. The 12 template tests and the asset crate's 99 tests pass.

  • 2.4 Write the fallback into a run's record. task-2-4

    The record's head in crates/htmlspec-cli/src/runs.rs writes the same constant, and a test reads it from a record a run creates.

    shell in crates/htmlspec-cli/src/runs.rs writes htmlspec_assets::fallback::ELEMENT after the record's title. the_record_carries_the_fallback_stylesheet_once in crates/htmlspec-cli/tests/run.rs starts a run, reads the fallback once in the record's head, and checks that the record passes strict validation and format --check. Against the record's previous head it failed, finding no fallback. All 36 run tests pass.

3. Existing documents

  • 3.1 Add htmlspec format --fallback. task-3-1

    Adds the fallback where it is absent and replaces one that differs, before canonicalization, and changes nothing else. It skips archived changes and run records and reports each one. It composes with --check, and the request-verb spelling takes it too. Plain format leaves a fallback present, absent, or stale as written (design decision 3). Test each of those, and that a second run changes nothing.

    htmlspec_format::fallback::apply in crates/htmlspec-format/src/fallback.rs works on the parsed head and serializes canonically. It places the element, parsed from the constant itself, before the head's first <link>, replaces a stale one's text, and returns a current one unchanged. The CLI composes it after reference filling, behind FallbackRequest::Apply. ProjectRoot::is_history names what it leaves alone: anything beneath the archive, and a document directly within a runbook's runs. Seven unit tests cover adding, current, stale, a second request, another <style> left alone, a head with no link, and refusing an ambiguous document. Six CLI tests in crates/htmlspec-cli/tests/cli.rs cover plain format leaving it absent, the request adding it once, --check --fallback reporting without writing, a stale one replaced only on request, history left as written, and put format --fallback. The parse test now gives format its --fallback. The workspace's 1484 tests pass.

6. Review and archival

  • 6.1 Take the code review, and settle each finding. task-6-1

    The review (medium) found two defects, and both were taken. First, the fallback moved the skip link off-screen and never brought it back, so where it applies a keyboard user tabbed onto a link nobody could see. The block gains .hs-skip-link:focus { left: 1.5rem; top: 1.5rem; }, the store's own values with --hs-gutter resolved. It stays inert, because the store's stylesheet sets both properties on that selector, and the element is now 794 bytes. the_fallback_brings_the_skip_link_back_on_focus failed against the old block and passes, and the_skip_link_check_reports_a_link_hidden_for_good holds the checker.

    Second, ProjectRoot::is_history resolved links before comparing, so an archived change or a runs directory reached through a link was judged by its target, and format --fallback rewrote through it. It now judges the path as spelled as well, as is_archived_change does. a_document_reached_through_a_symbolic_link_into_history_is_history failed before the fix and passes. The 13 accepted specifications and this change's documents were reformatted with --fallback, each gaining exactly the focus rule's line, and the release runbook and the archive are untouched.
