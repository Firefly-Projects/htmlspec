2. The road

  • 2.3 Write publish/patterns.tsv and publish/scan. task-2-3

    The patterns of design decision 6. The scanner matches text files case-insensitively, exits 0, 1, or 2, reports each match by file and line, lists the binary files it skipped, and refuses when one is not named in READINESS.md. Run against this repository as it stands, it reports every hit the audit found and nothing else.

    21 patterns in five sections: the private organization, the private project with its directory, subject, and change names, the contributor's home directory, the contributor's email address and this repository's address, and the two other private projects the audit looked for. Run as publish/scan --ref on this branch at 32589fc, before any rewrite, it reported 179 matching lines, all in files the rewrites touch: the private organization in 3 files, the private project in 23, home-directory paths in 17, and the address in Cargo.toml. Nothing else matched, among the minified scripts, the code, and the README included. It listed the four images as read. That was every hit the audit had named, and not every hit there was: reading the first rehearsed export (3.2) found the contributor's home directory on an earlier machine, which no pattern named. The pattern file gained it and two shape rows matching any home directory, 25 patterns, and run again at 49b9fc3 the scan reports path hits in 48 files rather than 17.

  • 2.4 Write publish/rewrites.tsv. task-2-4

    28 rows, and the rows for the private organization, the private project, and the home-directory paths name the glob * rather than a file, with the total count across the files it names, because the private project's change names turned out to reach 23 files, the shipped instruction source and its installed copies among them (design decision 4, amended).   • 2.5 Write publish/export. task-2-5

    The steps of design decision 2: refuse a dirty tree and an unknown ref, fetch the target's main, replace its contents with git archive of the allowlisted paths, rewrite, scan, run scripts/check in the exported tree, and commit with the source ref and commit in the message. --dry-run, --push, --bootstrap, and --remote-url as the decision describes.

    Python 3 with the standard library, sharing publish/publishing.py with the scanner. It reads the allowlist, both tables, the readiness record, and the identity from publish/ at the ref, builds in a scratch repository, refuses a target sharing any commit with this repository, and refuses an allowlisted path nobody recorded as read. The bootstrap commits the exported README.md and LICENSE after the whole tree has passed. PUBLISH_CHECK_COMMAND replaces scripts/check for the tooling's own tests. Design decision 2 records what the decision had not settled.
