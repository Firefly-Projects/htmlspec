Publish a public tree

Version 1.0 is html-spec's first public release, into a fresh public repository, Firefly-Projects/htmlspec. Nothing has left this private repository before, and its tracked files hold private material: two names of a private organization, a private project quoted at length, local paths, and this repository's own address. This change builds the one road out: a script that exports a listed tree from a committed ref, rewrites the private material it knows about, refuses when any private pattern survives, runs the whole suite inside the exported tree, and opens a pull request in the public repository. It adds the MIT license. It publishes nothing: the first export runs after the 1.0.0 change.

Why

The contributor decided the shape of the release on 2026-10-16. Version 1.0 goes to a fresh public repository, Firefly-Projects/htmlspec, and this repository stays private as the working record. A public repository descended from this one would carry every private blob in its history, however clean its last commit looked. A fresh one carries only the trees that are exported into it, so the export is the only place the boundary can be held.

What must not cross, measured on this branch's 1,487 tracked files, on 2026-10-19. This document names none of it literally, because it crosses too: the exact strings live only in the private rewrite table and pattern file.

The precedent is the contributor's skills export. The pull-request export in the contributor's skills repository builds each export as an ordinary commit on top of the target repository's own main, so a pull request can review it, and it rests on four controls: an allowlist decides what crosses, content comes from a committed ref through git archive and never from the working tree, a rewrite step stops when the text it expects is gone, and scan-public.sh refuses on any match against a private pattern file that never leaves the private repository. The contributor asked for the same road here, repeatable for every later release.

What working looks like

  1. publish/export --ref main --dry-run refuses a dirty working tree, exports the allowlisted paths from that committed ref into a scratch checkout, applies every rewrite, scans the result, runs scripts/check inside it, reports, and pushes nothing.
  2. A rewrite whose expected text is gone stops the export, naming the file and the text it expected.
  3. A private string planted in an allowlisted file stops the export at the scan, naming the file and the line, and nothing is committed.
  4. A local run builds the export in a scratch repository, keeps it, and prints its tree and the command that shows exactly what a pull request would show. --push and --bootstrap refuse unless they are handed that tree as reviewed.
  5. Against a scratch target repository, --push commits the export on a branch on top of the target's main, with the source ref and commit in the message, and opens a pull request, or replaces its branch and updates the pull request already open for that source. --bootstrap makes the first commit of an empty target, with no parent. No commit of this repository's history reaches the target. Every commit's author and committer are a GitHub noreply address.
  6. A file added under an allowlisted path after its read, and an image whose bytes changed since its read, stop the export. A PNG's text chunks are scanned.
  7. From this repository, the pre-push hook refuses every push to the public repository, tags included.
  8. In the exported tree, the private organization's names read example-corp and example-corp-product-team, the private project reads missile-launcher, no path names the contributor's home directory, Cargo.toml names https://github.com/Firefly-Projects/htmlspec, and the README says in one line that main is protected by a ruleset.
  9. Neither tree holds main-guard.yml, and the exported tree holds no publish.yml and nothing of publish/: not the script, the allowlist, the rewrites, the pattern file, or their tests.
  10. Both trees hold an MIT LICENSE, Copyright (c) 2026 Firefly Systems LLC.
  11. scripts/check passes here and inside the exported tree. This is release 0.32.0.

What changes

A publish/ directory holds the road out, and stays in this repository. It holds the allowlist of paths that may cross, the table of rewrites, the scanner and its pattern file, the export script, and a readiness checklist that a person signs before a path joins the allowlist. The rewrites and the patterns name the very strings they guard against, so none of it is published.

The export reads a committed ref, not the working tree. This repository tags no release today, so the ref is a branch or a commit until the 1.0.0 change adds a release tag to the release runbook. It runs the suite inside the exported tree before it commits, because the rewrites touch the archive and the migration fixture, which the release check and the migration tests read. A rewrite that broke a test is found before anything leaves this machine.

This repository's own records stay as written. The rewrites apply to the exported copy only. Each export commit names its source ref and commit, so the record behind a public file is always one lookup away.

A LICENSE file. MIT, Copyright (c) 2026 Firefly Systems LLC, the contributor's choice of holder.

The guard moves to the source. A ruleset protects this repository's main already, so main-guard.yml is deleted here, and the README and the pre-push hook say so. The hook also refuses any push from this repository to the public one, because a push from here would carry this repository's history.

The program in this repository does not change. The public copy's instructions differ in one example: it names a change of the private project, and the rewrites give it the neutral name there.

Alternatives considered

Make this repository public. Rejected by the contributor. Its history holds every private blob, and a clean last commit does not withdraw them.

Rebuild an orphan branch on every export, as the skills repository's export-public.sh does. Rejected. GitHub sees two unrelated histories and cannot open a pull request between them, so a branch ruleset on the public main could not admit a release.

Leave the archive and the migration fixture out. They hold every hit, so leaving them out looks attractive, and it fails twice. scripts/check-release exits 2 when a project has no archived changes, and nine migration survey tests read the fixture. The public tree would check less than this one, and its own documents, the strongest demonstration it has, would be missing.

Rewrite this repository's records in place. Rejected. The archive is history, and the private repository is the working record. Only the published copy needs the rewrites.

Use a generic secret scanner. Rejected as the main control. The exposure here is named private material, not credentials, and the skills scanner's own header gives the same reason: its patterns are the markers an audit found.

Scope

In scope. The publish/ directory and its parts, the LICENSE file, the rewrites for every row of the table above, the retirement of main-guard.yml with the README and hook corrected, the hook's refusal of pushes to the public repository, and release 0.32.0. A test run of the whole road against a scratch target repository, which proves every step short of the real public repository.

Not in scope. The four distribution channels belong to ship-through-four-channels. Contract 1.0.0 and a stable command line belong to commit-the-contract-and-the-command-line. The first real publication, and the creation of Firefly-Projects/htmlspec with its branch ruleset, happen after that change, as part of the 1.0.0 release. A scan that runs in the public repository's own continuous integration is left for a later change: every release reaches it through this export, already scanned.

Settled by the contributor. The private project counts as the private organization's information and becomes missile-launcher. The quoted evidence also names that project's local directory and changes that describe its industry, its equipment, and its data sources, and the contributor decided on 2026-10-16 that those names are rewritten too, into the same neutral theme.

Requirements. The contract is silent on publication. This change adds one requirement to toolchain-packaging, an obligation on the project's repositories like "The project records what changed in each version it ships": the project's public repository receives only trees exported from its private working repository, found clean by the scan, passed by the suite, and reviewed by a person as the exact tree pushed, and no commit of the private repository's history reaches it.

The release. 0.32.0, as the plan the contributor reviewed numbers it. project-bootstrap's "Archival requires the project version to advance" requires a new version and leaves its size to judgment. The program is unchanged, and the release adds the license and the publishing road.
