Publish a public tree

What this change established. The project's public repository receives only trees exported from its private working repository through a road that can refuse at every step: an allowlist, counted rewrites, a scan against a private pattern file, the suite run inside the exported tree, and a person's review of the exact tree pushed, in commits that carry no history of the private repository and a GitHub noreply identity. The change also adds the MIT license held by Firefly Systems LLC and retires main-guard.yml, which a branch ruleset already replaced. Release 0.32.0.

toolchain-packaging

The public repository receives only reviewed exports of the private one req-the-public-repository-receives-only-reviewed-exports

The project's public repository SHALL receive only trees exported from its private working repository. Each tree SHALL come from a committed ref of the private repository, through the allowlist of paths that may cross, with every rewrite applied at the count it expects, found clean by the scan against the private pattern file, passed by the project's full suite run inside the exported tree, and reviewed by a person as the exact tree that is pushed.

Each export SHALL arrive in a commit whose only parent is the public repository's own main, or with no parent for the first commit of an empty public repository, made by a GitHub noreply identity as author and committer, and naming its source ref and commit. No commit of the private repository's history SHALL reach the public repository, and the private repository SHALL refuse any push of its own to the public one, tags included.

The publishing tooling, its allowlist, rewrites, pattern file, and tests, SHALL stay in the private repository and SHALL be absent from every export, because its tables name the material they guard against.

What the change did that no requirement states

The repository gained an MIT LICENSE, Copyright (c) 2026 Firefly Systems LLC, the holder the contributor chose, which makes the license = "MIT" that Cargo.toml already declared true. .github/workflows/main-guard.yml is deleted, and the README and .githooks/pre-push no longer describe it, because a branch ruleset already protects the private repository's main. The contract is silent on both, and neither becomes a requirement here.

The rewrites apply to the exported copy only. The private repository's archive and the migration fixture stay as written, and the program in the private repository does not change: the public copy's instructions differ only in one example, which names a change of the private project and reads the neutral name there.

Evidence

The road, rehearsed against a scratch target evidence-the-road-rehearsed-2026-10-18

Against an empty local bare repository, with the sign-off of a throwaway branch marked as a rehearsal: an unsigned bootstrap was refused; the bootstrap made the target's first commit; the final push exported every allowlisted path, applied the rewrites, scanned clean, and passed all 13 stages of the suite inside the export. Reading the pushed tree found a second home directory of the contributor's that no pattern named, which the rewrites and the pattern file then covered. evidence/the-road-rehearsed-2026-10-18.md

The road, rehearsed again after the plan's review evidence-the-road-rehearsed-again-2026-10-19

After the revisions the review of the plan asked for: a push or bootstrap without --reviewed, and a push naming the wrong tree, were refused with nothing pushed; the bootstrap pushed a parentless commit of README.md and LICENSE; the push landed a branch whose only parent was that commit; a second push of the same source replaced its branch. 1,477 files, 23 rewrites covering 212 occurrences, a clean scan with four images read at their blob ids, and 13 of 13 stages passing inside the export. The target held no commit of the source, no blob of the tooling, and only the noreply identity. evidence/the-road-rehearsed-again-2026-10-19.md
