    • Each operation's arguments moved, with their doc comments unchanged, into one Args struct, 19 in all, and each OpenSpec variant now carries its struct.     • Both spellings reach one handler through Invocation, one variant per Operation, each carrying that operation's struct.     • Help is written from the table by operation::with_request_verbs, and main now parses against that command (get_matches_mut, then from_arg_matches), which is what Cli::parse does. A verb's help lists each object as "Runs htmlspec <spelling>." and its operation's description. An object's help is its operation's after that line. The verbs' text says they "name the effect … and send nothing"

    • Three unit tests were added in main.rs. the_command_line_offers_exactly_the_operations_under_both_spellings walks clap's tree and requires its paths to equal the table's two spellings of every operation. both_spellings_of_every_operation_parse_to_one_invocation parses each operation's spellings with every option and the global flags, and requires one Invocation of that operation. every_option_is_given_in_the_parse_tests requires that test to give each long option and positional argument clap declares. Of the existing tests, the consistency, help, and --json tests now run on the command as presented and cover the verbs, and the two that matched the old struct-like variants (the_defaults_are_whole_project_and_human_readable, the_withdrawn_init_path_parses_so_it_can_be_reported) match the new ones; what they assert is unchanged

    • Nothing the old main.rs said was lost: every string literal it held is in the new one, and of its doc comment lines only one changed, a test's comment, which now says the check runs on the command as presented

The case now uses an absent path, and the finding is recorded in 5.4

    • cargo test -p htmlspec-cli: 461 unit tests and 241 integration tests across the 10 test files pass. cargo clippy -p htmlspec-cli -p htmlspec-assets --all-targets -- -D warnings is clean
