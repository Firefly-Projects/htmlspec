  • 5.7 State equally plainly what is new: one obligation in this set is mechanically checked, and the assertion rule now carries a test an agent can apply to its own sentence.

    Neither makes the first rule checkable, and saying so is the point.

    Done. Two things are new and neither is a check on the assertion rule.

    First, one obligation in this set is mechanically checked end to end. review/example-content reports a unit carrying a template's example identifier, both operations that reach the accepted specifications refuse while one survives, the identifiers are derived from the compiled templates so a template that gains a unit is covered without a second edit, and a conformance fixture pins the half-replaced case. That is a real check, and it covers requirement 4 of five — not requirement 2, which is the one the change is named for.

    Second, the assertion rule now carries a test an agent applies to its own sentence: remove the claim's subject and read what is left. That is a procedure rather than a check — nothing runs it and nothing reports its result — and its purpose is to bound the rule rather than to enforce it, because a rule that fires on every sentence is one an agent learns to skim. Task 5.4 confirmed it does not over-fire.

    Neither of these makes requirement 2 checkable, and saying so is the point. The failure mode this change exists to prevent is a plausible sentence with a reason attached, and no mechanism this project can build distinguishes that from a correct one. Recording the boundary is what stops the next release from inheriting the belief that the rule is enforced.

    A third thing is new and belongs to the project's own files rather than to the obligation: scripts/check-installed closes the drift task 5.1 found by hand, and it caught the version-bump restaling on its first release

    Added after review of PR #21.
