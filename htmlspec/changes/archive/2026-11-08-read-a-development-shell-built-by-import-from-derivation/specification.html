Read a development shell built by import from a derivation

What this change established. A toolchain check over a local locked Nix flake reads a development shell that imports from a derivation whose output this machine's store holds, refuses one whose output the store lacks without building it, locally or on a remote builder, or substituting it, whatever the machine's configuration says, and quotes the package manager's error that states the cause. A download the shell asks Nix's own downloader for fails without leaving the machine. runbook-portability's "Package manifests retain authority over package pins" gains two scenarios that say so; its statements are unchanged. No command, flag, exit code, or payload field changed, and the release is the patch 1.3.2.

runbook-portability

Package manifests retain authority over package pins req-package-manifests-retain-authority-over-package-pins

A requirement for a package-managed toolchain SHALL identify the existing manifest, selected environment, and tools needed from it rather than repeat the manifest's versions in the runbook. Preflight SHALL delegate interpretation of pins to that package manager's supported read-only adapter and check the tools the invocation would actually use against that environment.

The initial supported package-manager adapter SHALL cover a local locked Nix flake's development shell. Preflight SHALL NOT install, build, download, update locks, enter a shell, or alter the working environment. Missing cached dependencies, an unsupported manifest, an unavailable manager, or an inability to establish a tool's provenance SHALL refuse readiness with an explanation. The existence of a manifest or a shell marker alone SHALL NOT count as evidence of readiness.

Given

When

Then
it reports the environment as unavailable, builds the derivation neither on this machine nor on a remote builder, nor substitutes it, and its explanation quotes the package manager's error that states the cause rather than the trace that came before it

The adapter that meets these scenarios is evaluation_arguments in crates/htmlspec-cli/src/preflight/host.rs. It evaluates with --offline, --option allow-import-from-derivation true, --max-jobs 0, --builders '', --option substitute false, --option connect-timeout 1, and --no-write-lock-file, in place of the --no-allow-import-from-derivation it passed from 0.15.0 to 1.3.1, which refused every import from a derivation, built or not. --option substitute false is stated because --offline turns substitution off only where no configuration set it. The evaluation's child has every proxy variable the operator set removed, http_proxy, https_proxy, and all_proxy, in both cases, pointed at 127.0.0.1:1, a closed local port, and GIT_PROXY_COMMAND and GIT_SSH_COMMAND set to false, so a download the evaluation asks libcurl or git for, a shell's own or a missing locked flake input's, is refused on this machine at once; a git input fetched with libgit2 where no git is on the search path, an s3:// fetch's credential lookup, and any other route are not covered. A failed evaluation's reason is quoted by evaluator_excerpt, from the first line that opens with error: and states something, or the first bare one followed by its message rather than a trace, to the end within 300 characters, without Nix's Hint: lines and terminal escapes; output with no such line is quoted from its first lines, and no other probe's quoting changed. No other accepted requirement changes: "Preflight gates the creation of a run" holds as it was, because a run observes through the same adapter, and toolchain-packaging's "The command surface is stable within a major version" holds because only the wording of a refusal's observed text and remedy changed. The release runbook's verification of its own toolchain check now describes the settings, so that runbook is 0.6.1.

Evidence

The refusal at 1.3.1, measured evidence-the-refusal-at-1-3-1

On 2026-11-08, on an aarch64-darwin laptop running Nix 2.34.6 (Determinate Nix 3.19.0), whose client is not a trusted user and which has one remote aarch64-linux builder configured. The reporting project's development shell builds a tool with import from a derivation. The 1.3.1 binary built from main at f4fc2a2 refused that project's toolchain checks, observing the manifest could not be evaluated read-only: error: / … while calling the 'map' builtin / at «string»:1:217:. The adapter's own command, run by hand, failed in one second and ended on error: cannot build '/nix/store/…​.drv^out' during evaluation because the option 'allow-import-from-derivation' is disabled, though that output was in the store. With --option allow-import-from-derivation true --max-jobs 0 --builders '' in place of the flag, the same command returned the shell's store paths and exited 0 in two seconds.

On a scratch flake whose shell imports a file one tiny derivation writes, the 1.3.1 flags refused the import with that same error whether or not its output was built. With the new settings a built import was read; one the store had never held was refused in under a second with error: Cannot build '…-htmlspec-import-from-derivation-fixture.drv'. / Reason: local builds are disabled (max-jobs = 0), and no output path appeared, for this machine's system and for aarch64-linux, which the remote builder could build. With the import allowed under --read-only instead, Nix built a fresh import's derivation, so --read-only is not a guard against building.

The new tests fail on the 1.3.1 adapter, and catch a build slot evidence-the-tests-against-1-3-1

Run against the 1.3.1 adapter before it changed, the argument test failed on the missing settings; the scripted evaluation that fails with a trace reported error: / … while calling the 'map' builtin / at «string»:1:193:; the real-Nix test of a built import failed on the refusal; and the real-Nix test of a missing import failed on its native case's reason, which quoted the trace. After the change all of them pass. With --max-jobs 0 changed to 1 for one run, the test of a missing import failed: its native import was built and the check went on to another refusal.

What the review of pull request 106 found, and what settled it evidence-the-review-of-pull-request-106

The review confirmed against Nix's source that the daemon honours --max-jobs 0 and --builders '' from an untrusted client, and found that without --builders '' the import built on a remote builder. It found three defects. First, a regression: --offline turns substitution off only where no configuration set substitute, so with NIX_CONFIG='substitute = true' the adapter downloaded a shell's missing dependency from a binary cache and reported it ready, where 1.3.1 refused. Measured here: nix config show substitute under that configuration printed true with --offline alone and with the adapter's earlier settings, and false once --option substitute false was added. Second, older than 1.3.2: a shell's builtins.fetchurl reached a listener on the loopback interface under the adapter's settings, 174 bytes of request, and with the child's proxy variables pointed at 192.0.2.1 and connect-timeout at one second nothing reached it and the fetch failed in 1.1 seconds. Third, where an import's own dependency was missing, the last error: line was Build failed due to failed dependency, and the cause came first; and a foreign import's platform mismatch fell past the excerpt's third line.

The real-Nix tests that settle the first two were each shown to fail without their fix: with --option substitute false removed, the substitution test and the argument test failed; with the child's proxy variables removed, the fetch test failed on a request reaching its listener. Under cargo test, DYLD_LIBRARY_PATH, which the harness sets for a test binary, made this machine's Nix start its first download ten seconds late, so the fetch test runs its request without that variable; the installed binary runs with no such path.

The new step of check.yml ran the real-Nix tests on Nix 2.22.1, which install-nix-action installs, and the test of a missing import failed there: the reason quoted the trace. Run here from that release's own binary, against a store in a scratch directory so its own worker declined the build, Nix 2.22.1 ends on a bare error: whose message, Unable to start any build; either increase '--max-jobs' or enable remote builds., follows on the next lines, for this machine's system and for another, and names no derivation. The excerpt now also starts at a bare error: followed by its message rather than a trace frame, joined to that message; the recorded output is pinned, and the test accepts either release's wording of the declined build.

The review's re-verification found nothing substituted under seven configurations and the excerpt right, and found the fetch closure incomplete. libcurl prefers the proxy variable named for a URL's scheme, so an operator's exported ftp_proxy carried an ftp:// builtins.fetchurl to that proxy past the child's all_proxy. git connected directly for git:// and SSH: its listener received git-upload-pack and an SSH connection. A missing git+https input timed out at the deadline, because git honours the proxy and not connect-timeout. And --offline had never kept a missing locked tarball, github:, or git+http input from being downloaded, in 1.3.1 as in 1.3.2. The child now has every variable ending in _proxy removed before the six are set, at a closed local port, 127.0.0.1:1, and GIT_PROXY_COMMAND and GIT_SSH_COMMAND at false; measured here, an ftp:// fetch through an operator's ftp_proxy, git:// and SSH fetches, and missing locked tarball and git+https inputs were each refused in under 0.2 seconds, and nothing reached the listener. The real-Nix tests now run their Nix with a cache directory of their own, so none touches the cache in this machine's home.

the_adapter_invocation_is_read_only_and_names_no_verb_that_provisions, in crates/htmlspec-cli/src/preflight/host.rs, compares every argument before the expression with a literal, because Nix takes the last value it is given for a setting and a later one would undo an earlier: eval, --offline, --option allow-import-from-derivation true, --max-jobs 0, --builders '', --option substitute false, --option connect-timeout 1, --no-write-lock-file, --impure, --json, and --expr. It asserts the child's environment whole: every variable ending in _proxy removed, the six proxy variables at http://127.0.0.1:1, and GIT_PROXY_COMMAND and GIT_SSH_COMMAND at false; an_operators_proxy_variables_do_not_reach_the_evaluation computes the child's environment from an inherited one holding an operator's ftp_proxy, socks_proxy, and no_proxy and finds only the six; and that none of develop, build, shell, fetch, run, profile, or install is an argument. a_failed_evaluation_quotes_the_error_rather_than_the_trace asserts the adapter sends exactly that environment, and a_probes_environment_reaches_its_child_alone that the real runner applies it to the child and not to this process. Repeat with cargo test -p htmlspec-cli --lib preflight::host.

A shell whose import the store holds is read, with real Nix verify-a-held-import-is-read

Through the real runner and the adapter's own arguments, the evaluation names that input, realized, and the declared toolchain check, observed with observe_all and judged with assess, is ready with its tool attributed to the input. No configuration turns substitution back on, with real Nix verify-no-configuration-turns-substitution-on

real_nix_substitutes_nothing_whatever_the_configuration_says runs nix config show substitute with NIX_CONFIG='substitute = true' on that child alone: without the adapter's settings it prints true, so the configuration reached the child, and with exactly the settings evaluation_settings returns it prints false. Ran on 2026-11-08 with the same Nix and the same command; with --option substitute false removed it failed.

No test substitutes an import from a binary cache: this machine's daemon ignores a substituter an untrusted client names, measured, so a cache in a scratch directory never reaches it, and a test against a public cache would need the network. The setting the substitution turns on is what is checked.
