Read a development shell built by import from a derivation: design

How the toolchain check reads a development shell that imports from a derivation without building anything, how its refusal comes to quote Nix's error, how real Nix is brought into the tests, and why the release is a patch, 1.3.2. It brings the adapter back to runbook-portability's "Package manifests retain authority over package pins", whose statements do not change; the requirement gains two scenarios, so it is a modified requirement at archival.

The gap

The toolchain adapter is evaluation_arguments and evaluate_inputs in crates/htmlspec-cli/src/preflight/host.rs. After refusing three cases without Nix (no manifest, no flake.lock beside it, no nix on the search path), it runs, from the flake's directory and under the probe's ten-second deadline:

nix --extra-experimental-features 'nix-command flakes' eval --offline --no-write-lock-file \
  --no-allow-import-from-derivation --impure --json --expr '…the shell's inputs' store paths…'

Measured with Nix 2.34.6 (Determinate Nix 3.19.0) on an aarch64-darwin laptop whose client is not a trusted user and which has one remote aarch64-linux builder configured:

  • Against the reporting project's flake, whose development shell builds a tool with import from a derivation, these flags fail in one second, ending on error: cannot build '/nix/store/…​.drv^out' during evaluation because the option 'allow-import-from-derivation' is disabled, though that output is in the store. The 1.3.1 binary's htmlspec preflight then reports error: / … while calling the 'map' builtin / at «string»:1:217:, the first three lines of the trace.
  • With --option allow-import-from-derivation true --max-jobs 0 --builders '' in place of the flag, the same evaluation returns the shell's store paths and exits 0, in two seconds.
  • Against a scratch flake whose shell imports a file one tiny derivation writes, the old flags refuse the import whether or not its output is built. With the new ones, a built output is read. An output the store never held is refused in under a second, ending on error: Cannot build '/nix/store/…-htmlspec-import-from-derivation-fixture.drv'. / Reason: local builds are disabled (max-jobs = 0) / Hint: …, and no output path appears. The same holds when that derivation is for aarch64-linux, which the configured remote builder could build.
  • With the import allowed under --read-only instead, Nix built the scratch derivation the store had never held.

The review of pull request 106 found three more things, each measured here. With substitute = true in NIX_CONFIG, --offline left substitution on, so those settings would download an import's missing dependency. A shell's builtins.fetchurl reached a listener on the loopback interface under every release's settings. And where an import's own dependency was missing, the last error: line Nix wrote was Build failed due to failed dependency, the cause coming first. Decisions 1, 2, and 4 record what settled each. Its re-verification found the fetch closure incomplete: an operator's own ftp_proxy carried an ftp:// fetch past the child's all_proxy, git:// and SSH fetches connected directly, a missing git+https input waited out the deadline because git ignores connect-timeout, and --offline had never kept a missing locked flake input from being downloaded. Decision 1 records what settled those, and the risks what stays open.

What the contract says

Accepted requirement Effect at archival
runbook-portability's "Package manifests retain authority over package pins" The requirement this change brings the implementation back to. Its statements do not change: the adapter "SHALL cover a local locked Nix flake's development shell", preflight "SHALL NOT install, build, download, update locks, enter a shell, or alter the working environment", and a refusal comes "with an explanation". The 1.3.1 adapter broke the first and the third for a shell that imports from a derivation, and let a shell's own fetch download, which broke the second in every release since 0.15.0. It gains two scenarios, one for an import whose output the store holds and one for an import whose output it lacks, neither built nor substituted, so the contract names the case that went wrong for five minor versions. The three scenarios it holds are carried forward unchanged, "Resolving the environment would require provisioning" among them. Modified.

toolchain-packaging's "The command surface is stable within a major version" Unchanged, and the reason the release can be a patch: no command, flag, exit code, or payload field changes. The words of a refusal's observed text and its remedy change, and "The wording of human-readable output is not covered." observed is a string field of preflight's payload and stays one. tests/surface/1.3.json does not move.
the release runbook's "The size of the increment is the contributor's decision" Unchanged. This design takes the decision it reserves: a patch, 1.3.2, in decision 6.
runbook-authority's "A runbook carries an independently checked release version" Unchanged. It is why the release runbook, whose verification text changes, moves from 0.6.0 to 0.6.1.

It requires the one command to run the unit tests, and it is silent on a test that needs a resource the suite's sandbox cannot hold, which the real-Nix tests of decision 4 do. Decisions

Allow the import, and forbid every build, substitution, and download decision-allow-the-import-forbid-the-build

evaluation_arguments drops --no-allow-import-from-derivation and passes the settings evaluation_settings returns: --offline, --option allow-import-from-derivation true, --max-jobs 0, --builders '', --option substitute false, and --option connect-timeout 1. Everything else in the vector stays: eval as the one verb, --no-write-lock-file, --impure for builtins.currentSystem, --json, and the same expression. Each setting closes one way to provision, and the comment beside each says which: --offline trusts the fetcher cache as it stands and asks no registry, though alone it keeps no missing locked input from being downloaded, which the child's environment below refuses; --max-jobs 0 leaves no local build slot; --builders '' leaves no remote builder; --option substitute false leaves no binary cache, whatever the configuration says. Between them an import whose output is valid in the store is read, because reading a valid output needs no build, and an import whose output is missing becomes a refusal Nix states itself.

The evaluation's child also changes its environment. Every variable whose name ends in _proxy, in either case, is removed; then http_proxy, https_proxy, and all_proxy, in both cases, name http://127.0.0.1:1, a closed local port; and GIT_PROXY_COMMAND and GIT_SSH_COMMAND are false. --option connect-timeout 1 bounds a wait should something drop rather than refuse a connection there. A probe's request carries such changes in a field of its own, environment, a static list of changes this module spells, applied to the child alone; the child's whole environment is computed from what this process inherited by a pure function, child_environment, and the other probes change nothing.

The flag's purpose, in carry-a-runbook-to-another-machine's design, was that "an input that would need a build to be understood is refused rather than built". The build settings keep that promise exactly and nothing beyond it, where the flag refused imports that needed no build. max-jobs reaches the daemon with every client's options and an empty builders is accepted from any client, so the settings hold for an untrusted client, which is what the measurements above ran as, and the review confirmed both against Nix's source. The --option form states a setting by name with its value, and the test asserts the whole vector, because Nix takes the last value it is given and a later one would undo an earlier.

Substitution. The first version relied on --offline, which turns substitution off only where no configuration set substitute; a line in nix.conf or NIX_CONFIG counts as set, and the daemon applies the client's choice for any client. The review found that regression, and stating the setting closes it whatever the machine says.

Downloads. --offline never stopped a download: every release since 0.15.0 let a shell's builtins.fetchurl, builtins.fetchTarball, or builtins.fetchGit reach the network during the check, and downloaded a locked flake input the machine lacked, a tarball, a github: input, or a git one. Nix's downloader is libcurl, and git fetches over HTTP with libcurl too; libcurl takes its proxy from these variables, preferring the one named for a URL's scheme, so the operator's own, ftp_proxy among them, are removed before the six are set, and it excepts no host once no_proxy is gone, loopback included, measured. git opens git:// and SSH connections itself, past any proxy, through GIT_PROXY_COMMAND and GIT_SSH_COMMAND, which outrank its configuration, so both are a command that fails. A static field rather than a parameter, so a carried runbook can no more set a variable on a probe than choose its arguments. What the variables do not reach is an accepted risk below.

The port. The first version named 192.0.2.1, which answers nothing, and relied on connect-timeout to end the wait. git does not read that setting, so a missing git+https input waited out the probe's ten seconds and was reported as timed out with nothing known; with a closed local port, every proxied connection is refused at once, measured at under 0.2 seconds for each route, and the refusal quotes the fetch that failed. Port 1, TCP's port-service multiplexer, is served by nothing in practice and on Linux takes root to bind; a process that did listen there would still be on this machine. Port 0, which no process can listen on, refused as fast here and was not chosen: one of libcurl's interfaces reads a proxy port of 0 as its default, 1080, where a local SOCKS proxy commonly runs, so a client that read a URL's :0 that way would hand the request to one. This choice is the design's own.

Rejected: --read-only. Measured above, it did not stop a build. Rejected: keeping the refusal. It contradicts "SHALL cover a local locked Nix flake's development shell", and a shell built with callCabal2nix or any other import from a derivation is such a shell. Rejected: leaving the setting to nix.conf. What preflight may do to a machine is the adapter's promise, so the adapter states it, and a flag on the command line overrides the machine's configuration in both directions. Rejected: --option download-attempts 1. A failed connection was not retried with the timeout alone, measured, and the daemon warns an untrusted client about a restricted setting it ignores.

Quote the first error that states a cause decision-quote-the-error-the-evaluator-ended-on

A failed evaluation's reason quotes a new function, evaluator_excerpt, in place of excerpt. It removes terminal escape sequences, trims each line, and starts at the first line that opens with error: and states something after it, or that is a bare error: whose message follows on the next line rather than a frame of a trace, joined to that line, as Nix 2.22 writes Unable to start any build; it passes over the bare error: that opens a trace. From there it joins every line to the end with / , leaving out Nix's Hint: lines, and cuts at 300 characters, on a character's boundary, with no limit of lines. Output with no such line is quoted by excerpt unchanged. So the trace's error: / … while calling the 'map' builtin / at «string»:1:217: becomes error: Cannot build '/nix/store/…​.drv'. / Reason: local builds are disabled (max-jobs = 0), a foreign import adds Reason: platform mismatch / Required system: …, and a missing dependency quotes the build Nix declined.

The first version quoted from the last error: line, on the reading that Nix writes its trace first and its error last. That holds for one missing import. Where the import's own dependency is missing, the realistic case after a garbage collection, Nix writes the build it declined first and ends on Build failed due to failed dependency, which names nothing; the review found it, and the first line that states something is right in every case recorded. The three-line limit hid a foreign import's platform mismatch, on the error's fourth to sixth lines, so the bound is characters alone. The Hint: line advises changing max-jobs or builders, which this adapter states and an operator cannot change for it, and leaving it out keeps the reason inside the bound; that one is this design's own choice. Nix 2.34.6 decides colour from isatty, TERM, and NO_COLOR, so it colours nothing written to a pipe, but a later Nix honours FORCE_COLOR and CLICOLOR_FORCE; removing escapes first makes the quote the same either way.

The function serves the evaluation alone, because the order of a refusal's lines is a fact about Nix. excerpt keeps quoting a tool's version output, git status, and an answer of the wrong shape exactly as it did, and the scope of the proposal says no other probe's quoting changes.

The refusal's remedy names an import from a derivation decision-the-remedy-names-the-import

The remedy of a failed evaluation becomes: make the environment inspectable from what this machine already holds, its locked inputs in the store, any file the shell imports from a derivation built there already, and the shell the declaration names in the manifest; entering the shell once realizes them; this probe builds, substitutes, and updates nothing, and lets none of Nix's own downloads leave the machine. The check's own remedy, "realize `…`'s `…` environment on this machine", is unchanged.

Once the import is allowed, a missing output is the one way an otherwise sound shell still fails here, after a garbage collection for instance, and entering the shell is what builds it again. The words say so where the reader is. They said the probe "fetches" nothing until the review, which a fetch by another route than Nix's downloader would make false, so they now say what the settings close.

Run real Nix in tests the suite marks ignored, and in a step of continuous integration decision-real-nix-in-an-ignored-test

The scripted tests stay. the_adapter_invocation_is_read_only_and_names_no_verb_that_provisions compares every argument before the expression with a literal, and the child's environment with its names and value. evaluator_excerpt is pinned on Nix 2.34.6's output for the 1.3.1 refusal, one missing import, a foreign one, a missing dependency, and a missing shell, with the scratch directory replaced by /work/project, and on output with no stated error: line, and coloured output quotes as plain. A scripted evaluation that fails with a trace reports the error and sends the environment, and a real child sees the environment its request names while this process does not.

Beside them, four tests run this machine's Nix. real_nix_reads_an_import_from_a_derivation_the_store_holds and real_nix_refuses_an_import_from_a_derivation_the_store_lacks_without_building_it run it through the real runner and the adapter's own arguments. Each writes, in a scratch directory, a flake with no inputs and its lock, whose default shell imports a Nix file one derivation writes with /bin/sh's echo alone, carrying a nonce so its output is one this store has never held. The shell's one input is a directory holding an executable, which the test writes and the flake copies into the store with builtins.path, because a sandboxed builder has no mkdir or chmod and the repository may track no executable file. The first builds the import with nix build, then runs the declared check through observe_all and assess and asserts the runbook is ready, its tool attributed to that input. The second never builds it, for this machine's system and then for another one, which a configured remote builder could build, and asserts the check is unavailable, its reason starts at Nix's error: and quotes the build Nix declined, which Nix 2.34 names and Nix 2.22 does not, and the output path is not in the store afterwards.

real_nix_substitutes_nothing_whatever_the_configuration_says runs nix config show substitute with NIX_CONFIG='substitute = true' on that child alone, first bare, where it prints true, then with evaluation_settings, where it prints false. real_nix_fetches_nothing_a_shell_asks_for listens on the loopback interface, which stands in for the network and for an operator's ftp_proxy, set before the adapter's changes as the operator's environment would hold it, and evaluates through evaluate_inputs seven shells: one whose input is builtins.fetchurl, builtins.fetchTarball, an ftp:// builtins.fetchurl, and builtins.fetchGit over git:// and over SSH, of a URL on it, and two whose locked flake input, a tarball and a git+https repository on it, no store or cache holds. It asserts each is refused within five seconds on a failed fetch, which Nix 2.34 words with the URL and Nix 2.22, after git fails, as a Git reference it cannot resolve, and that no connection arrives. Its first run in continuous integration, on Nix 2.22.1, failed on that wording alone; that release's own binary, run here with the adapter's environment, refused the git://, SSH, and https fetches in under 0.4 seconds with nothing reaching a listener. With the suffix removal, GIT_PROXY_COMMAND, or GIT_SSH_COMMAND taken out alone, a request reached the listener; with the proxy back at 192.0.2.1:9, the git+https input timed out.

Every real-Nix test runs its Nix with a cache directory of its own, so none reads or writes the cache in this machine's home, and without DYLD_LIBRARY_PATH, LD_LIBRARY_PATH, and their kin, which cargo test sets for a test binary: under the first, measured, this machine's Nix started its first download ten seconds late, so the deadline ended the evaluation before any request, with or without the proxy, and the test could not tell the two apart. The installed binary runs with neither. A test runner wrapping the real one adds both to every request, so the tests still go through the host and the adapter's own request.

All four are #[ignore], with a reason that names how to run them: cargo test -p htmlspec-cli --lib -- --ignored real_nix, from inside nix develop or anywhere Nix is installed. check.yml runs exactly that, in a step after the suite. The README says so under Checks. No test substitutes from a binary cache: this machine's daemon ignores a substituter an untrusted client names, measured, so a cache in a scratch directory never reaches it here.

The suite runs in the Nix build sandbox, which has no daemon and no store to write, and in check-without-nix.yml, which has no Nix, so a test that needs real Nix cannot be one the suite runs. A test that passed itself where Nix is absent would be a skipped assertion that reads as a pass, which this module's other tests refuse to be: they panic when sh or git is missing. #[ignore] is shown as ignored in every run and is the repository's existing shape for such a test, the surface's recording test in surface.rs. The first version left a step of check.yml to a later change; the review asked for it, and it is here. install-nix-action makes that runner a trusted user, whose settings the daemon applies whole, so continuous integration exercises the trusted client's path only; an untrusted client's, whose settings the daemon filters, is checked by hand, as it was for this change on Nix 2.34.6.

The flakes are written by the tests, as the module's other toolchain tests write theirs, rather than kept under fixtures/, which holds documents. Each test makes its own nonce from the process and the clock, so two runs never share an output, and a present-case output left in the store is a few bytes a garbage collection removes.

The README and the release runbook describe the settings decision-the-documents-stop-describing-the-flag

The README's paragraph on the toolchain check says the evaluation runs offline with lock updates, substitution, local builds, and remote builders disabled whatever the machine's configuration says, that a shell importing from a derivation is read when this machine holds what the import reads and refused, neither built nor substituted, when it does not, and that a download the shell asks Nix for is sent where nothing answers. The release runbook's verification verify-the-pinned-toolchain says the evaluation is offline with no build slot and no remote builder, where it said "with import-from-derivation disabled". Its text changes, so the runbook moves from 0.6.0 to 0.6.1, a patch, with a changelog entry saying its steps and requirements are unchanged. No other tracked file outside the archive names the flag: the accepted specifications, the instruction bodies, and the publish runbook never did, and an archived change is history and is left as written.

Both described the flag as the reason the check builds nothing, and a description that names a flag the program no longer passes is one a reader would check and find false. The runbook's steps, their order, and its requirements do not change, so its increment is a patch, as the publish runbook's 0.2.1 was for a change of the same size. The runbook's sentence names two of the settings and not substitution or the proxy; it stays as archival published it at 0.6.1, true as far as it goes, because a further edit would be a further release of the runbook for words alone.

A patch release, 1.3.2 decision-a-patch-release

The release is opened as the release runbook's first three steps open one: cargo xtask set-version 1.3.2, which rewrites the workspace version, every internal pin, and the lockfile; htmlspec init --tools claude,codex,pi from the root with the 1.3.2 binary, which restamps each installed instruction file's generatedBy, checked by cargo xtask check-installed; and a ## 1.3.2 entry in CHANGELOG.md with an Upgrading note. spec.nix moves to 1.3.2 at archival, in the same pull request.

A patch fixes a defect and changes no surface, and this one adds nothing the surface records. A runbook that passed on 1.3.1 passes on 1.3.2 unless its shell fetched or substituted during the check, which the contract never allowed; a runbook that failed only because its shell imports from a derivation passes. The contract's own version, 1.0.0, does not move.

Risks

A large shell can approach the ten-second deadline on a cold machine risk-a-cold-machine-near-the-deadline

An evaluation the flag used to stop at the import now runs through the whole shell: two seconds here, warm, in the reported case. On a cold machine, or a slower one, a larger shell could come near the probe's ten-second deadline, and one that passed it would be reported as timed out, which is unavailable readiness naming the bound. The change bears it: the deadline is the design's, a timeout is a refusal with its reason rather than a wrong answer, and every shell that took this long would have been refused outright by 1.3.1. A shell that imports from no derivation is evaluated with the same work as before.

Measured rather than assumed: the reported shell evaluates in two seconds, a fifth of the deadline.

A garbage collection can remove what the import reads risk-garbage-collection-removes-the-import

Nothing roots an import's output: nix develop builds it and keeps no reference to it, so nix-collect-garbage deletes it, and the dependencies it was built from. The check then refuses as unavailable, which the requirement allows for "missing cached dependencies", and builds and substitutes nothing to get it back.

The refusal explains itself: its observed text starts at the first error: Cannot build '…', which names the derivation it would have had to build, the import or a dependency of it, and its remedy says that entering the shell once builds it.

A Nix that ignored a client's settings would build or substitute risk-a-nix-that-ignores-the-settings

The guarantee rests on the daemon honouring max-jobs, an empty builders, and substitute from the client that asks, where the flag rested on the evaluator alone. A Nix that dropped one for an untrusted client would build or substitute an import whose output is missing, which "SHALL NOT build" and "SHALL NOT download" forbid.

Measured on Nix 2.34.6 as an untrusted client with a remote builder configured, for this machine's system and for the builder's, and confirmed by the review against Determinate Nix 3.19.0's source, where the daemon applies max-jobs and substitute for any client and accepts an empty builders from one. Held by the refusal and substitution tests, which check.yml runs on each pull request as a trusted client; an untrusted client's path is held only where someone runs those tests as one.

Colour could hide the error line risk-colour-hides-the-error-line

Nix 2.34.6 decides whether to colour from isatty, TERM, and NO_COLOR, so it colours nothing it writes to the probe's pipe. A later Nix honours FORCE_COLOR and CLICOLOR_FORCE, which the probe would inherit from the operator, and then no line would open with error: as text and the excerpt would fall back to the first lines.

evaluator_excerpt removes terminal escape sequences before it reads a line, and a test holds that coloured refusals quote as plain ones.

A fetch by a route the child's environment does not reach is not stopped risk-a-fetch-by-another-route

The child's environment closes what libcurl fetches, for Nix and for git, and git's own git:// and SSH connections. Three routes stay open, and a shell that fetched by one during the check could still reach the network. Where no git is on the child's search path, Nix fetches a git input with libgit2, which ignores the proxy variables (git-utils.cc, lines 640 to 678, in Determinate Nix 3.19.0), so a git+http input can bypass the proxy. An s3:// fetch looks its credentials up from the cloud's container and instance metadata endpoints (aws-creds.cc, lines 324 to 391), which it reaches directly. And any interpreter or program the evaluation runs by a route outside libcurl, git, and the variables named. The change bears them: no release before 1.3.2 stopped any fetch, each route is unusual for a development shell's inputs, and closing them means configuring libgit2's transport and the credential chain, which a later change can do once it can test each.

A store that forwards no settings would build or substitute with its own risk-a-store-that-forwards-no-settings

Where the machine's configured store is an ssh-ng:// store, the client forwards none of its settings, and the remote daemon builds or substitutes with its own configuration. The check could then provision on that remote machine. The change bears it: such a store is an unusual default for a machine that runs a project's development shell, the store's paths would not be on this machine's filesystem, so the check would refuse after the evaluation anyway, and refusing up front means asking Nix for its store in a second process on every toolchain check, and changing every scripted test of the probe for a case none of them has.
