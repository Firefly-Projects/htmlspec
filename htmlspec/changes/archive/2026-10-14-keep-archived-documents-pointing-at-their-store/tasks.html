1. Tests first

Each test is run against the unrepaired build before the fix, and the run is recorded in this change's evidence: each one that tests a defect must fail there for the reason the defect gives.

  • 1.1 Add a CLI test that archives a change and checks every reference its documents carry. task-1-1

    In a scratch project, archive a change whose documents reference the store, an accepted specification through ../../specs/, and a file of their own through evidence/ and tasks.html#…, and whose evidence holds an HTML file with a ../../assets/ reference. Assert that the archived documents reference ../../../assets/ and ../../../specs/, that the references within the change are unchanged, that the evidence is byte for byte what it was, and that htmlspec validate and htmlspec format --check accept the archive.

  • 1.2 Add unit tests for the rewrite, in htmlspec-format. task-1-2

    A reference leaving the directory is re-expressed from the new one. One inside it is unchanged. A scheme, an absolute path, a bare fragment, and an empty value are unchanged. A query and a fragment are kept. A value in text, or in an attribute outside the two sets, is unchanged. Every byte outside a rewritten value is copied through. A reference that leaves the directory and comes back into it is re-expressed by where it lands.

  • 1.3 Add validation tests for a reference's path. task-1-3

    A document whose asset reference names stored bytes through a path that reaches another directory fails htmlspec validate with asset/unresolved, and the message names where the path leads and where the store is. The same reference spelled to reach the store is accepted. htmlspec format leaves the misplaced reference as it was written.

  • 1.4 Add recovery tests for the staged documents. task-1-4

    An interruption before the move removes the staged copies with the inventory, and leaves each document as it was. An interruption after the move puts each staged copy in place of its document and clears the journal. A v1 journal is still settled. A change that already holds a staged copy is refused, naming it.

2. The fix

  • 2.1 Add the rewrite to htmlspec-format, beside asset_references. task-2-1

    It finds values with the tag scanner, reads REFERENCING_ATTRIBUTES and a href and area href, resolves each relative path lexically against the directory before the move, and re-expresses it from the directory after (design decisions 1 and 2).

  • 2.2 Stage, journal, and promote the rewritten documents in archival's transaction. task-2-2

    In perform, write each rewritten document beside the inventory as .<name>.archiving, journal it, and replace the document with it after the rename. The journal becomes v2. Recovery completes the replacements, and reads v1. The leftover check refuses a change holding a staged copy (design decision 3).

  • 2.3 Resolve an asset reference through its path in validation. task-2-3

    Give the store a view from a document's directory, add the resolution for a reference whose path reaches another directory, report it as asset/unresolved, and have htmlspec validate hand the rule the store seen from each document's directory (design decision 4).

  • 2.4 Run the tests from 1.1 to 1.4, and the existing archival, validation, and formatting suites, and see every one pass. task-2-4

    The first full run failed two existing fixtures in tests/cli.rs that archived a change by renaming it, which is the defect: their documents referenced ../../assets/, and validation now rejects that. Neither test is about the store, so the fixtures were corrected to re-express their references as archival now does, and kept every assertion. evidence/the-tests-before-and-after-the-fix-2026-10-14.md records both runs.

3. The contract

  • 3.1 At archival, state the rewrite in a modification of "Archival produces the specification and updates the accepted contract". task-3-1

    Archival re-expresses each relative reference in the change's documents that would otherwise reach another file from the archive, leaves evidence as it was, and does so inside the transaction, with a scenario for each.

  • 3.2 At archival, state the path in a modification of "An asset reference must match the bytes it names". task-3-2

    An asset reference resolves only where its path, from the document, reaches the store's directory, with a scenario for a reference that names stored bytes through a path reaching another directory.

5. Review and archival

  • 5.1 Prove the tests can fail: undo each repair in turn, and record which tests fail. task-5-1

    Undo the rewrite, the promotion after the rename, the recovery's completion, and the path check, one at a time, and record in this change's evidence the tests each one fails. Then restore the repair.

    Seven repairs were undone in turn. Six were each caught by at least one test. The leftover check was caught by none, because the test's leftover was for a document archival rewrites, and staging the rewrite refused over it for another reason. The test now also leaves one for a document archival does not rewrite, and fails with the check undone. evidence/mutation-testing-2026-10-14.md records every run.

  • 5.2 Take the code review, and settle each finding. task-5-2

    The review of pull request #58 (medium) found two low-severity issues, and both were taken. First, the path check compared a reference's directory with the store's as text relative to the document, so ../../../htmlspec/assets/, which a browser loads from the store, was rejected. A reference now leads to the store when the directory it names, followed lexically from the document's absolute directory, is the store's; the filesystem is never asked, so the verdict is the same on every machine (design decision 4). Second, a staged copy written part-way by a run killed before the move was refused as somebody's edit. Recovery now removes a staged copy in a change that never moved whatever it holds, and still refuses an edited one after the move (design decision 3). Each repair has a test that failed against the reviewed head. evidence/the-code-review-of-pull-request-58-2026-10-14.md records both runs.

  • 5.3 Archive the change with htmlspec archive. task-5-3

    It is the first archival that runs the rewrite on this repository, so check that its documents reference ../../../assets/ without a hand repair, and record it.

    Archived on 2026-10-14 as 2026-10-14-keep-archived-documents-pointing-at-their-store, at version 0.30.0, by the binary this change builds. Archival reported "re-expressed 30 reference(s) in 4 document(s), so each reaches from the archive what it reached from the change": the 28 asset references now climb to ../../../assets/, and the two links to the accepted requirements this change modifies to ../../../specs/. No staged copy and no journal were left behind. Every relative reference in the project's 165 documents was then checked against the files on disk, and none names nothing. The archive's runbooks.json lists no runbook, because the release runbook still sits outside the project. Archival asked about this task, the only one open while it ran, and was answered with --yes.
