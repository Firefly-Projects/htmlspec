Subject
Writing, running, and reviewing a runbook through agent workflows

Tasks

Each task is one unit of work, individually addressable, so a state change is a change to one unit rather than to a list. The groups run in order, because each needs the one before it. Group 1 opens 1.4.0 on a main that holds 1.3.3. Group 2 writes the bodies, which group 3's rows compile in and its installation copies out. Group 4 revises the publish runbook. Group 5 says it all in the README and the changelog. Group 6's dry run is the evidence group 7's specification cites. Group 8 checks and reviews the whole, and group 9 archives it. The accepted specifications change only through group 7's merge and group 9's archival, never by a hand edit outside that path. Suites and export rehearsals run under the shared suite lock. Nothing here starts a run of this repository's publish or release runbook: the 1.4.0 publish run comes after archival, under the run workflow, and it is not a task of this change.
