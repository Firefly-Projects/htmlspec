1. The check, before the fix

  • 1.1 Add a test in crates/htmlspec-cli/src/install.rs that installs for every tool in TOOLS, collects the name: value from every skill and command file that tool receives, and asserts no value appears twice within one tool.

    Scope it per tool: two tools declaring htmlspec-apply-change is correct, since each tool's namespace is its own

  • 1.2 Make the failure name the tool, the repeated value, and both file paths.

    "A name is duplicated" across 21 files is not actionable

  • 1.3 Run it and watch it fail on the 21 command files that Claude Code, Cursor, and Pi currently receive — 7 each.

    This is the naturally occurring failing case and the only chance to see the check work

  • 1.4 Record the failure output as evidence, with the per-tool count.

    Confirm Codex does not appear: it is SkillsOnly, so it has no second file to collide with

  • 1.5 Confirm every_generated_name_is_loadable passes throughout.

    Both duplicates are well-formed, so the character check is blind to this fault — that is the reason a second check exists rather than an extension of the first

    Migration note: confirmed for its character assertion only. On the tree before the fix, every_generated_name_is_loadable reported no malformed name, and the non-vacuity assertion the same commit added to it failed, 49 declared names against the 28 expected, so the check did not pass throughout. evidence/failing-distinctness-check-2026-08-20.md records this as a qualification.

2. Stop writing the name

  • 2.1 Change write_commands in install.rs to omit name: from the generated frontmatter, keeping description, allowed-tools, and generatedBy.

    generatedBy is required by an accepted requirement about recording the generating version and must not be dropped along with the name

  • 2.2 Replace the comment added by the previous change.

    It currently explains why the name is workflow.directory rather than the invocation; it must now explain why there is no name field at all, and record that the file path determines the invocation

  • 2.3 Confirm workflow.directory still has a caller in write_skills, so the field is not left dead

  • 2.4 Re-run the test from task 1 and confirm it passes

  • 2.5 Run the full suite.

    every_generated_name_is_loadable must still pass — it now reads only skill files' names for the three tools that changed, and it must not have become vacuous. Confirm it still finds 7 names per tool rather than 0

4. Prove the omission does not break loading

  • 4.1 Regenerate this repository's instructions with htmlspec init --tools claude,codex,pi and confirm the 14 command files no longer carry name:.

    14 here, not 21: this repository selects claude,codex,pi and Codex is skills-only

  • 4.2 Confirm the seven /htmlspec:* commands still load and are still invocable.

    This must be checked by loading rather than by reasoning — it is the risk that would make the change wrong rather than merely different. Closed by a session load on 2026-08-21, after the merge of #6 and the profile upgrade to c864727. The commands load and remain invocable, so omitting name: from a command file does not change what a contributor types

  • 4.3 Confirm a session load now lists seven html-spec entries rather than fourteen.

    That count is the symptom this change exists to remove, and it is the only direct check that it worked. Closed by a session load on 2026-08-21. The doubled listing is gone. This is the observation the opsx comparison could only argue for

  • 4.4 Record the result as evidence, including the opsx comparison: ten .pi/prompts/opsx-*.md omit name: and load, which is the reason to expect this to hold

  • 4.5 Note in the evidence that Cursor's command loader was not tested, since this repository does not select Cursor.

    The design records this as an accepted risk and it must not be reported as verified
