1. Re-measure before changing anything

  • 1.1 In a copy of HEAD, run htmlspec init --tools none, then htmlspec assets ., and record the exact count and every location reported.

    The expected count is nine. Record the actual count, because the proposal and the design both rest on it

  • 1.2 In the same copy, run htmlspec validate over fixtures/ and over the new htmlspec/.

    Check whether any stage other than self-assets changes result when htmlspec/ exists, and record the answer. The proposal claims only the topology check is affected

2. Tests first

  • 2.1 Add CLI tests for the four scenarios in specs/document-validation/spec.md: a project beside a fixture store, a project beside a root toolchain store, two stores inside the project, and an outside store that duplicates within itself.

    Check that the first two fail on HEAD and the last two pass on HEAD

  • 2.2 Add a test that assets and the promotion check give the same verdict on the same tree, so that one of them cannot drift from the other

3. The partition

  • 3.1 Write one function that partitions discovered stores into the project's and the others by canonical path prefix against ProjectRoot::htmlspec(), and unit-test it with a symlinked path and with a store at htmlspec/assets itself

  • 3.2 Use it in assets: compare across the project's stores only, and check each outside store on its own.

    Check that the tests from 2.1 pass

  • 3.3 Use it in the promotion check in place of its separate topology loop.

    Check with cargo test -p htmlspec-cli --test promote

  • 3.4 Report the partition in the human report and as projectStores and otherStores in the structured payload.

    Check that the existing payload keys keep their values in the existing tests

4. The suite

  • 4.1 Correct the self-assets comment in scripts/check

  • 4.2 Repeat 1.1 against the built change and record the result.

    The expected result is zero duplicates. If any are reported, record what they are before changing anything else

5. Prove it

  • 5.1 Mutation-test the change.

    Make the partition return every store as the project's, then make it return none, and check that a test catches each case

  • 5.2 Run cargo test --workspace --all-targets, then scripts/check, with every stage green

    Migration note: no record is of this task's own run. evidence/the-runbook-ran-2026-09-27.md records that in the release run, once the stray htmlspec/ and spec.nix were removed, "scripts/check then passed all 13 stages", and scripts/check at dfb2b04 runs cargo test --workspace --all-targets --locked as its test stage. Nothing records cargo test --workspace --all-targets run on its own.

  • 5.3 Record what the implementation revealed

6. Release

  • 6.1 Run the release runbook at runbooks/release/tasks.html, and report whether it worked as written

  • 6.2 Choose the increment and state the reasoning, and flag it for confirmation
