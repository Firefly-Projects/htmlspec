Confine the asset check to the project

Under "A project must not store one asset's bytes more than once", a project's stores are the asset stores within its own htmlspec/ directory, and the comparison across stores is made among those stores alone. A store outside that directory is still checked on its own and compared with no other store, and the report states which stores it treated as the project's and which it checked on their own.

document-validation

A project must not store one asset's bytes more than once req-a-project-must-not-store-one-asset-s-bytes-more-than-once

Validation SHALL reject a project that stores identical asset bytes at more than one location. The report SHALL name every location holding the duplicated bytes, so a contributor can tell which copy to remove.

Two assets whose bytes differ SHALL NOT be reported as duplicates, however similar their names, versions, or purposes.

This rule takes a project as its subject rather than a document, so it SHALL be evaluated where a project is in view. A directory holding no asset store has nothing to duplicate, and SHALL NOT be reported.

A project's stores SHALL be the asset stores within the project's own directory, htmlspec/, and no others. The comparison across stores SHALL be made among those stores alone. A repository holding a project can hold other stores that are not the project's — a conformance fixture that is a project of its own, a toolchain's source copy of the runtime, a vendored copy another tool reads — and bytes those stores share with the project's are not the project storing its bytes twice. The subject of this rule is one project, and a comparison that reaches past the project's directory has changed its subject to the repository.

A store outside the project's directory SHALL still be checked on its own, so a store that holds identical bytes at two of its own locations is reported wherever it lives. It SHALL NOT be compared with the project's stores or with any other store.

The report SHALL state which stores it treated as the project's and which it checked on their own, so a contributor can tell a duplication that is not the project's from a check that did not run.

Where no project is in view, every store SHALL be checked on its own, as before.

The measurement, repeated before anything changed evidence-the-measurement-2026-09-27

Tasks 1.1, 1.2, and 4.2, run in a git clone of 51c5aea, the merge of #35 and 0.16.0 (evidence/the-measurement-2026-09-27.md). With htmlspec 0.16.0, before init, htmlspec assets . checked 14 stored assets in 5 stores, each on its own, and found each once. After htmlspec init --tools none, it checked 22 in 6 stores, reported 9 duplicated assets, and exited 1: eight runtime files in both ./assets/ and ./htmlspec/assets/, and one stylesheet two conformance fixtures both carry. With and without the htmlspec/ and spec.nix that init created, every document stage of scripts/check and a validation of every fixture document gave identical results, and the one difference was validate htmlspec, whose path did not exist without them. With the binary built from this change, the same tree reported 1 store within the project's htmlspec/ and 5 outside it, each checked on its own, found each stored asset once, and exited 0, with "projectStores": ["./htmlspec/assets"], the five others under "otherStores", "stores": 6, and "storedAssets": 22. A copy of htmlspec/assets/ at htmlspec/changes/a-change/assets/ reported 8 duplicated assets and exited 1. A store is now named by its assets/ directory, a readability fix made on the way.

Mutation testing the partition evidence-mutation-testing-2026-09-27

Task 5.1 (evidence/mutation-testing-2026-09-27.md). Each of three mutations edited partition in crates/htmlspec-cli/src/topology.rs alone, ran cargo test -q --no-fail-fast -p htmlspec-cli, and restored the file. "Every store is the project's", the behavior before this change, was caught by five named tests, among them a_project_beside_a_fixture_store_is_not_a_duplicate_of_it and a_project_beside_a_toolchain_source_store_is_not_a_duplicate_of_it. Paths compared without resolving symbolic links were caught by a_project_reached_through_a_symbolic_link_keeps_its_stores alone, which exists because macOS reaches the temporary directory through /var → /private/var.

What the implementation revealed evidence-what-the-implementation-revealed-2026-09-27

Task 5.3's seven findings (evidence/what-the-implementation-revealed-2026-09-27.md). One of task 1.1's nine duplicates was between two conformance fixtures, with no project store involved: once any project resolved, every store was compared with every other. Only the topology check depends on the project's existence. The partition compares canonical paths, falls back to the absolute path where a path cannot be resolved, and one test fails without it. A store is named in the report by its assets/ directory. The partition is stated whenever a project is in view, including "No store outside it was found", and the structured payload always carries both lists. Promotion resolves the staged tree as a project and passes the staged root to the same topology::check as assets, and the_asset_check_and_promotion_give_one_verdict keeps the two from drifting. The proposal's non-goals remain.

The release runbook's run for 0.17.0 evidence-the-runbook-ran-2026-09-27

Tasks 6.1 to 6.3, against the release runbook at version 0.1.0 (evidence/the-runbook-ran-2026-09-27.md). The increment, 0.16.0 to 0.17.0, was a minor one, confirmed by the contributor before the version moved. With the stray htmlspec/ and spec.nix that init bootstrapped present, htmlspec assets . exited 0, reporting 1 store within the project's htmlspec/ and 5 outside it, each checked on its own, where before this change it reported nine duplicates.
