## The release workflow on the pull request

Pull request 102, labelled `release-check` when it was opened, so its first run built all four
targets. The `opened` and `labeled` events started two runs at once, and the workflow's concurrency
group cancelled the first, 41564168720, as it does any superseded pull request run. Run
41564169040, at `523ab88`, passed verify, plan, the four builds, sums, and formula; suite, release,
crates, tap, install, and install-homebrew were skipped, as they are on every pull request.

- **The tools were handed on.** sums and formula each ran the composite action: the artifact
  downloaded, `tar -xf "$DIRECTORY/xtask.tar"`, and `xtask --help` printed the tools' usage, so the
  binary kept its executable bit through the artifact. plan ran it too.
- **sums** packed the four bare binaries, `dist/htmlspec-1.3.1-aarch64-apple-darwin.tar.gz` and the
  other three, wrote `SHA256SUMS` in the facts' order, four lines, and rendered the formula, its
  header `# Rendered by cargo xtask render-formula ...`, its four addresses
  `https://github.com/Firefly-Projects/htmlspec/releases/download/v1.3.1/htmlspec-1.3.1-TARGET.tar.gz`,
  each with the digest `SHA256SUMS` gives it.
- **formula**, on `macos-15`, took the tools of the `aarch64-apple-darwin` build, `xtask-macos`, and
  ran `xtask check-formula dist` against the runner's own Homebrew: `=== brew audit --strict ===`,
  `=== brew install ===` with `/opt/homebrew/Cellar/htmlspec/1.3.1: 7 files, 17.7MB`,
  `=== brew test ===` with `htmlspec 1.3.1 (d79c8120ae4a)`, the pull request's merge commit, and
  `the formula audits, installs, and passes its test`, with no warning that a trust was left.
