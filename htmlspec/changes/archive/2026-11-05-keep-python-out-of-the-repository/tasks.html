  • Tasks

Tasks

Each task is one unit of work, individually addressable, so a state change is a change to one unit rather than to a list. A group is one pull request, merged after one review, and the groups merge in order. Four rules hold for every group. The parity rule: before a Python file is deleted, each of its test cases has a named Rust counterpart, the pull request lists the pairs, and one deliberate break per group of cases shows the counterpart fails. The rename rule: a comment, header, or document line that names a script is rewritten in the pull request that deletes the script. The pin rule: an edit to a pinned Python file updates its entry in the same commit, and a deletion removes its entry. The rehearsal rule: before a group lands, the reads of every allowlisted path it changed are recorded in publish/READINESS.md, and publish/export --ref HEAD --dry-run runs against an empty local bare repository and passes, its result recorded in the pull request.
