What was built

The repository's checks read the project. scripts/check-release names the project's directory once, PROJECT = Path("htmlspec"), and reads the archive at htmlspec/changes/archive, the adoption marker at htmlspec/runbook-releases.json, and the runbooks at htmlspec/runbooks. It checks 38 archived changes where it checked 36, so the two releases archived with htmlspec archive, 0.29.1 and 0.30.0, are checked by the suite for the first time. The self-runbooks and self-runbooks-format stages of scripts/check validate and format-check htmlspec/runbooks.

The release runbook is in the project, unchanged. runbooks/release/ moved with git mv to htmlspec/runbooks/release/, four renames with no line changed, and its VERSION is still 0.1.0. The two stylesheet revisions its documents link, sha256-e4f5de7cecc4f691 and sha256-0350261bb5666167, were copied from the root assets/ into htmlspec/assets/, which the root keeps as the toolchain's source copy. htmlspec list --runbooks lists release.

The OpenSpec project is the migration tests' fixture. openspec/ moved with git mv to fixtures/migration-source/openspec/, 473 renames with no line changed. crates/htmlspec-cli/tests/migrate.rs reads every survey and every independent walk from fn source(), which names fixtures/migration-source, and still reads the repository's CHANGELOG.md, scripts/check-release, the schema, and migrate.md, because it cross-checks the source against them. The repository root holds no openspec/ and no runbooks/.

A test that reads the repository's places fails when one is missing. The presentation checks in conformance/tests/presentation.rs read the documents migration kept in htmlspec/changes/*/evidence/documents/ and htmlspec/changes/archive/*/evidence/documents/, and fail when no change holds such a directory. The asset rules' agreement test in crates/htmlspec-validate/src/rules/assets.rs reads README.html, assets, fixtures, and htmlspec, and fails when one of them is missing. Before, both skipped a place they could not read and passed. The second edit is inside the module's tests, so no code the program runs changed.

The OpenSpec workflows are removed. The 52 files under .claude/skills/openspec-*, .claude/commands/opsx/, .codex/skills/openspec-*, .pi/prompts/opsx-*, and .pi/skills/openspec-* were removed with git rm. Each ran the openspec command against the directory this change moved.

The repository's prose follows the move. The comments in scripts/check-release, scripts/check, and migrate.rs that the edits touch, scripts/check-installed's docstring and comments, and flake.nix's source-filter comment no longer say this repository governs itself with openspec/ or is not a project. The migration plan and the eleven logs of its review are carried, byte-identical, as this change's evidence.

Release 0.30.1. Cargo.toml, Cargo.lock, and CHANGELOG.md were advanced to 0.30.1, a patch increment chosen because nothing the program does changes. The 45 installed instruction files were regenerated with htmlspec init --tools claude,codex,pi, one generatedBy line each, and spec.nix was raised to 0.30.1 at archival.

Requirements

This change adds, modifies, and removes no requirement. What it changed is where this repository's checks and tests read, and the contract is silent on where this repository keeps its project. The obligations that name the repository say what its checks establish rather than where they look: toolchain-packaging's "The project records what changed in each version it ships", which it places on this repository, and project-bootstrap's "The release suite checks published runbook version history", which it places on the repository's release suite. Both are met by the checks reading htmlspec/, as the verification below records.

The contract is also silent on one thing this change relies on. project-bootstrap's "Archival checks the versions of runbooks it publishes" orders snapshots by recorded project version and keeps a deleted runbook's snapshots, and runbook-authority identifies a runbook by its directory's name. Neither says whether a runbook absent from some archives and present again under its name continues one history or begins another. The program continues it: predecessor in crates/htmlspec-cli/src/runbook_release.rs compares a runbook with the last snapshot that has its name, so release is compared with 0.29.0's snapshot across the archives of 0.29.1 and 0.30.0, which each recorded an empty inventory because the runbook was outside the project. This change preserves that behavior and does not state it. A change that wants it held states it as a requirement.

Not established here. No stage validates the whole of htmlspec/, which is a separate decision. The program's source comments that cite evidence by its pre-archive path, and the one in crates/htmlspec-cli/src/install.rs that cites the removed .pi/prompts/opsx-*.md files, are left for repoint-the-sources-evidence-citations. The release runbook's text is not revised, and it does not describe this repository: its step for regenerating the instruction files says to remove the htmlspec/ and spec.nix that are now the project. The next change, release-a-repository-that-is-its-own-project, revises it.
