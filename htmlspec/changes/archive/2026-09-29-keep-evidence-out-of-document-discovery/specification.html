Keep evidence out of document discovery

Under artifact-kinds' "A change's evidence is kept in the change and is not one of its documents", a change directory, active or archived, may hold an evidence/ directory, and every file beneath it is a record of the change rather than a document of the project, which no operation of the program rewrites. Under toolchain-packaging's "An operation over a directory collects documents and not a change's evidence", an operation that collects documents by walking a directory within a project passes over a change's evidence, while a path a contributor names is still checked and format's writing mode refuses to write a record. Under project-migration's "Evidence crosses unchanged", carried evidence is outside the conformance checks run over a staged project, so it does not gate promotion.

artifact-kinds

A change's evidence is kept in the change and is not one of its documents req-a-change-s-evidence-is-kept-in-the-change-and-is-not-one-of-its-documents

A change directory MAY hold an evidence/ directory directly within it. Every file beneath that directory, at any depth, SHALL be the change's evidence: a transcript, a measurement, a recorded complaint, or a document preserved as it was written. It is a record of why the change has the shape it does.

Evidence SHALL NOT be a document of the project. An evidence file declares no artifact kind, owes conformance to no contract version, and does not reference the project's asset store. The obligations this contract places on "every document in the project", including "A project has a declared root holding one asset store", do not reach it. Its format is its author's choice: Markdown, plain text, a script, or HTML.

The reason is the one project-migration's "Evidence crosses unchanged" already gives: a record's worth is that nobody edited it. A contract that held evidence to the rules for documents would require each record to be rewritten whenever the contract moved. A record written in this format at an earlier contract version, or naming an asset store that has since been removed, would have to be edited or deleted. Either act destroys what the record was kept for.

The location is positional. A directory named evidence is a change's evidence only where it sits directly within a change directory, active or archived. The same name anywhere else, such as a capability whose path is evidence, carries no special meaning.

No operation of the program SHALL rewrite a file beneath a change's evidence, including one a contributor names. Checking one is permitted, because a check writes nothing.

toolchain-packaging

An operation over a directory collects documents and not a change's evidence req-an-operation-over-a-directory-collects-documents-and-not-a-change-s-evidence

When validate or format, in either its writing or its checking mode, is given a directory or no path at all, it SHALL operate on every .html file beneath that directory, except files beneath a change's evidence as artifact-kinds' "A change's evidence is kept in the change and is not one of its documents" places it. Every other operation that collects a project's documents by walking a directory SHALL make the same exclusion from the same definition.

A path the contributor names SHALL be checked as named. A file means that file. A directory that is itself a change's evidence directory, or lies beneath one, means that directory, and validate and format --check SHALL check every .html file beneath it. The exclusion applies to what a walk comes across and never to what a contributor asked for. A contributor who wants to know whether a record still conforms can ask, and the answer is the ordinary one.

Checking is not writing. format in its writing mode SHALL NOT write a file beneath a change's evidence, including one a contributor names, because artifact-kinds states that no operation rewrites one. Given such a path, it SHALL name each record, write nothing at all, and exit with the status for an operation that could not run. It SHALL NOT write the other documents and skip the records. A partial write would report success for a request it half ignored.

Where the walked directory is not within a project, no directory is a change's evidence, and every .html file beneath it SHALL be operated on. A conformance fixture and a loose directory of documents keep the behavior they have.

The exclusion SHALL be defined once and reached by every such operation. It SHALL NOT be restated per command. A second definition that drifts from the first would have validate and format disagree about which files are documents. That is the fault this requirement exists to remove, arriving by another route.

project-migration

Evidence crosses unchanged req-evidence-crosses-unchanged

A source change's evidence files SHALL be carried into the migrated change unchanged, and SHALL NOT be converted into the destination format.

Evidence is a transcript, a measurement, or a recorded complaint, and its worth is that nobody edited it. Converting one is rewriting a record, and a rewritten record cannot serve the purpose evidence serves.

The migrated change's documents SHALL reference the carried evidence, so that a reader reaches it from the document that cites it rather than by finding it in a directory.

Carried evidence SHALL NOT be subject to the conformance checks run over the staged project. Those checks are the project's own, and a change's evidence is not a document of the project. So a record that is already in the destination format neither gates promotion nor is rewritten by it, even at a superseded contract version or naming an asset store the project does not hold. That includes a document preserved under "A source entity already in the destination format is not assumed usable". A requirement to carry records unchanged, paired with a check that refuses them, would leave a migration only two choices: edit the record, or leave it behind.
