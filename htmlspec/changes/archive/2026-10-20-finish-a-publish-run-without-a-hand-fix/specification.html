Finish a publish run without a hand fix

What this change established. The development shell supplies the interpreter the project's suite and runbooks run, so a script run inside it uses the shell's python3 rather than the machine's. An export's commit and its pull request are titled by the version the exported ref declares and a twelve-character commit id, held before anything is exported to the title rules the ref itself states, which are the ones the public repository's guard applies. Both gaps stopped the first run of the publish runbook, the v1.0.0 release, and each needed a fix by hand.

toolchain-packaging

The toolchain builds reproducibly from pinned inputs req-the-toolchain-builds-reproducibly-from-pinned-inputs

The project SHALL be buildable from fully pinned inputs, including the compiler toolchain, every dependency, and every vendored browser-side library. Building the same revision SHALL produce equivalent results regardless of what is already installed on the machine.

Then

The public repository receives only reviewed exports of the private one req-the-public-repository-receives-only-reviewed-exports

The project's public repository SHALL receive only trees exported from its private working repository. Each tree SHALL come from a committed ref of the private repository, through the allowlist of paths that may cross, with every rewrite applied at the count it expects, found clean by the scan against the private pattern file, passed by the project's full suite run inside the exported tree, and reviewed by a person as the exact tree that is pushed.

A tree SHALL reach the public repository only from a commit the private repository's main holds, so that the reads of its paths and the contributor's sign-off it is delivered under are ones a reviewed pull request landed. A read SHALL name the content it covers, so that it survives the squash merge that lands it, and every file under an allowlisted path whose content differs from the content its read names, added or changed since, SHALL be refused, each one named.

Each export SHALL arrive in a commit whose only parent is the public repository's own main, or with no parent for the first commit of an empty public repository, made by a GitHub noreply identity as author and committer, and naming its source ref and commit. No commit of the private repository's history SHALL reach the public repository, and the private repository SHALL refuse any push of its own to the public one, tags included, under any spelling of the public repository's address.

An export's commit subject, which is also its pull request's title, SHALL name the version the exported ref declares and the commit's first twelve characters, and SHALL pass the title rules the ref itself states, the ones the public repository's guard runs from the exported tree, before anything is exported. A ref that states no such rules SHALL be refused. The first commit of an empty public repository opens no pull request and carries a fixed subject, so it needs neither.

The publishing tooling, its allowlist, rewrites, pattern file, and tests, SHALL stay in the private repository and SHALL be absent from every export, because its tables name the material they guard against.

Evidence

The first publish run needed two fixes by hand evidence-the-first-publish-run

The first run of the publish runbook, the v1.0.0 release on 2026-10-20, passed its preflight inside nix develop and stopped at its second step. publish/export exited with "error: tool 'python3' not found": on macOS, /usr/bin/python3 asks the developer tools at DEVELOPER_DIR for the interpreter, and the shell points that at the Nix SDK, which has none. The run continued outside the shell. Its export then opened Firefly-Projects/htmlspec#1 titled Export htmlspec from 7983c4a9003176c8a2483cb03e6efb599d82d2ab at 7983c4a90031, 77 characters, and the public repository's guard refused it as over 72. The title was edited by hand to Export htmlspec 1.0.0 from 7983c4a90031, and the guard passed. GitHub took the squash commit's subject from the commit message, so the public history keeps the long one.

Which interpreter runs, inside the shell and outside it evidence-the-shells-interpreter

Inside nix develop on macOS, python3 resolves to /nix/store/76pkfxf6miplkp915lgi5kk4qlc2wav9-python3-3.13.14/bin/python3 and prints Python 3.13.14. Outside it, python3 resolves to /usr/bin/python3 and prints Python 3.9.6, and htmlspec preflight publish reports the runbook not ready. With pkgs.python3 taken out of the shell again, the code review saw "error: tool 'python3' not found" return inside it.

Verification

The suite and the publishing scripts run inside the shell verify-the-shell-runs-its-own-interpreter

On macOS, nix develop -c scripts/check passed all 14 stages, its Python stages included, and nix develop -c publish/export --ref HEAD --dry-run against an empty local bare repository ran to the end with every check passing inside the exported tree. publish/test passed 51 tests under the shell's Python 3.13.14 and under the system's 3.9.6. Inside the shell, htmlspec preflight publish reports the runbook ready.

An export's title is held to the ref's title rules verify-an-export-is-titled-within-the-guards-rules

publish/test's test_an_export_of_a_full_commit_id_is_titled_within_the_guards_rules pushes an export of a full commit id and finds its subject and the pull request it would open titled Export htmlspec 1.2.3 from and twelve characters, with no fault under scripts/check-pull-request's rules. test_a_title_the_guard_refuses_stops_the_export_before_anything_is_exported, test_the_title_rules_are_the_refs_and_not_the_checkouts, and test_a_ref_without_the_title_rules_stops_the_export see a subject over the limit, a ref whose rules are stricter than the checkout's, and a ref without the rules each refused before the export starts. test_a_bootstrap_needs_no_version_and_its_subject_keeps_the_title_rules bootstraps a ref with no version. With the rules read from beside the export rather than at the ref, the stricter-rules test fails. A dry run of this repository's export onto a target that has a main passed the title check with the subject Export htmlspec 1.0.1 from 7f92d68cb10f.

No export has yet opened a pull request in the public repository under the new title, so the public repository's guard itself has not judged one.
