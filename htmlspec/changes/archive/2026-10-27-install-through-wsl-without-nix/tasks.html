Install htmlspec on Windows through WSL, without Nix: tasks

The work that makes WSL the documented Windows route and the routes without Nix as clear as the one with it. It covers the README's install and contributor sections, an offline test of the install blocks, a continuous-integration job without Nix, an install job that runs the README against every release, and the publish runbook's record of it.   • 3.3 Install every release through the README task-3-3

    Two jobs in the release workflow (design decision 7):

    install, with needs: release, on ubuntu-24.04 and ubuntu-24.04-arm. It polls releases/latest for about five minutes until it redirects to /tag/$TAG. It ends as skipped, with a notice, when the latest names a newer version (a patch on an older line), and fails with "latest is not $TAG" when the bound passes otherwise. Then it extracts the marked Linux block from the README at the tag, runs it verbatim with bash -x and an empty HOME, requires the tag's version, and runs init, new change, and validate in a scratch project.

    install-homebrew, with needs: tap, on ubuntu-24.04, running the Homebrew-on-Linux block verbatim with bash -x and requiring the tag's version.

    Both carry if: github.repository == 'Firefly-Projects/htmlspec' && startsWith(github.ref, 'refs/tags/v'), as every job after release does. Lint the workflow with actionlint, and record which jobs run where.

    Both jobs are in release.yml with the needs and the condition the task gives. A running job cannot mark itself skipped, so for a patch on an older line install ends with a notice and the steps after it are skipped, and the job succeeds. The polling step was run on 2026-10-27 against the live latest release: v1.1.0 was ready, v1.0.0 ended with the notice, and v1.2.0 failed with "latest is not v1.2.0" once the bound passed. Which jobs run where: both run only on a version tag in Firefly-Projects/htmlspec, and neither runs on a pull request or in this repository. Their downloads therefore wait for the 1.1.1 publish. actionlint 1.7.12 with ShellCheck 0.11.0 reports nothing in any workflow.
