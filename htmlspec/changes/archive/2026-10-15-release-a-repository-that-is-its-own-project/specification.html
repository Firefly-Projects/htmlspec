What was built

The regeneration step removes nothing. task-regenerate-the-instructions in htmlspec/runbooks/release/tasks.html keeps its first four sentences and replaces the removal of htmlspec/ and spec.nix. A run regenerates from the repository root with the binary at the new version, saves what git status --short --untracked-files=all lists first, and removes nothing afterwards. It stops if init reports that it created the project structure, or if git status lists a path it did not list before, outside the root's .claude/, .codex/, and .pi/ and the assets init reports establishing in the store. Then it runs scripts/check, and the step names the release and self-runbooks stages as the ones that read the project rather than self-assets.

The hazard is a new requirement of the runbook. The runbook's specification loses req-init-bootstraps-a-stray-project and its two scenarios, and gains req-regenerating-leaves-the-project-in-place, with three scenarios: the removal 0.1.0 required, followed; regenerating in the project, with the version advance and the change being released uncommitted; and regenerating from another directory. evidence-nine-duplicate-assets is retold in the past tense, and the measurement of the removal against the project and a verification of the new requirement are added.

The recorded version is described as htmlspec archive writes it. req-the-recorded-version-waits-for-archival keeps its identifier and heading. A run does not write the archived change's VERSION, and raises spec.nix at archival to the version it set in Cargo.toml, and a scenario covers spec.nix raised to another version. task-confirm-the-release-check says the same.

The other statements the reading found false are corrected. The specification's masthead, the input that assumed a repository without a project, risk-the-inputs-are-prose, the count of the release check's questions, three where it asks four, and risk-this-runbook-goes-stale, which now records what happened. The two other steps, the other four requirements, both decisions, and the history before 0.1.0 read as they did. Every unit of both documents declares unchanged and every step is todo.

Requirements

This change adds, modifies, and removes no accepted requirement. The requirements it replaced and restated are the runbook's, which its specification states are what it requires of a run and not obligations of the project, as runbook-authority's "A runbook records what its history taught" provides. The accepted requirements the change meets are that one, which makes the turned-over hazard a requirement rather than a remark; "The canonical procedure carries no completion state", which keeps every step todo; "A runbook carries an independently checked release version"; and project-bootstrap's "Archival checks the versions of runbooks it publishes", which requires the strictly greater version the changed documents owe.

The contract is silent on whether spec.nix and Cargo.toml must declare the same version. Cargo.toml's is what the binary reports and what the release check reads as declared, and spec.nix's is what archival compares and records. Nothing compares the two. The runbook requires a run to raise spec.nix to the workspace version, which preserves what each release since promotion did, and that is the runbook's requirement of a run. The release check notices a mismatch only while no changelog heading names the stray version.

The contract is silent on whether init searches upward for a project. project-bootstrap's "Commands resolve the project from any directory beneath it" requires that search of every command whose subject is a project, and does not say whether init is one. Run from crates/, it establishes a second project there. The runbook names the root and stops on the report. Settling it is a change to the program, bootstrap-beneath-a-project.

Not established here. The four Python stages failing inside nix develop on macOS, which the runbook now states as a fact about the shell rather than as a hazard. The runbook's documents keep their contract version, 0.1.0. The runbook was not run: htmlspec run release --as … writes a record of a run that happened, and no release was performed by it.
