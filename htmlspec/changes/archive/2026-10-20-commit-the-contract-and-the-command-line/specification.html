document-schema

The contract's version is a semantic version req-the-contract-s-version-is-a-semantic-version

The contract's version SHALL be a semantic version. A major release MAY withdraw or reshape a unit, a field, or a projection rule. A minor release adds vocabulary, and MAY add warnings and review findings. A patch release changes wording and fixes defects.

Within a major version from 1 on, a document that one version accepts SHALL be accepted by every later version of that major: no later minor or patch SHALL report an error on it that the earlier version did not, except where the earlier version accepted what a requirement stated at that version refused, a defect the release's changelog names. Warnings are outside this promise.

The schema SHALL keep accepting every version a minor or patch release succeeded, and SHALL keep accepting 0.1.0 to 0.7.0 beside 1.x. Version 1.0.0 is the 0.7.0 vocabulary, unchanged. A document the toolchain writes, from a template or as a run's record, SHALL declare the newest version, in its head and wherever its masthead names the contract.

toolchain-packaging

The command surface is stable within a major version req-the-command-surface-is-stable-within-a-major-version

Within a major version, every operation SHALL keep its name in both spellings, the OpenSpec spelling and the request-verb spelling, and every alias it accepts. Every flag SHALL keep its name, its short form, its aliases, and its meaning, and an optional argument SHALL stay optional. Every exit code SHALL keep its value and its meaning. Every field of every --json payload SHALL keep its name, its type, and its meaning, a field always present SHALL stay present, and a value an enumeration admits SHALL stay admitted. --help, -h, --version, -V, and the help subcommand SHALL stay. A minor release MAY add any of them, and only a major release removes or renames one. The wording of human-readable output is not covered.

Each operation that writes a payload SHALL publish a JSON Schema for it under crates/htmlspec-cli/schema/payload/, declaring every field it can emit. A published schema SHALL admit a property it does not declare, and SHALL say that a later release of its major can add one and that a consumer ignores a property it does not know. The program SHALL write no field its operation's schema does not declare. Where run --as starts no run because the machine falls short of a prerequisite, its payload SHALL be the preflight report, and run's schema SHALL state that shape.

The surface each released minor makes SHALL be recorded, read from the program's own parser, in crates/htmlspec-cli/tests/surface/<major>.<minor>.json. The project's checks SHALL fail when the program lacks anything a released surface of its major holds, when a later file of a major lacks anything an earlier one holds, when the declared version's minor has no file, when the current minor's file does not record the current surface, when the parser accepts a command no operation spells, and when a field a schema declares appears in no payload the tests produce.

Evidence

Each break the requirement names fails a test evidence-each-break-fails-a-test-2026-10-20

Each change was made in the real program and then reverted. Renaming --strict to --strictly failed the surface comparison with four lost facts. Moving the cancelled exit code from 3 to 4 failed it. Removing openTasks from status's payload failed five tests on the required property. Moving the version to 1.1.0 failed with no 1.1.json. At review, an alias fetch on the verb get and a short alias -s on --strict each failed the comparison of the current minor's file, naming the new spellings. With --strict renamed, the test that rewrites the surface refused and named the three lost facts, leaving the file unchanged. An outcome added to the exit type and left out of the list stopped the surface tests compiling at the test's placement match.

Documents declaring every earlier version validate unchanged evidence-earlier-versions-validate-unchanged-2026-10-20

The review validated 87 documents, the 81 conformance fixtures and 6 of this repository's own, each declared at 14 versions, with the 0.34.0 binary and with this change's. For 0.1.0 to 0.7.0 the output and exit codes were byte for byte the same. 1.0.0 is newly accepted. 1.1.0, 2.0.0, 0.8.0, 1.0, 1.0.0-rc.1, and v1.0.0 were refused by both. A run's record written by the 0.34.0 binary, declaring 0.1.0, still reads, passes run --check, and validates.

Verification

The program holds every released surface of its major verify-the-surface-holds-every-released-surface

cargo test -p htmlspec-cli --bin htmlspec surface. src/surface.rs builds the surface from the parser, walking every command under its name and every alias at every level, and fails on a command no operation spells. Its tests compare the program with tests/surface/1.0.json as sets of facts, require the current minor's file to equal the current surface, require the declared minor to have a file, compare files only within a major, and hold the writer to refusing a loss. Ten more each edit a surface one way and require the loss, or the absence of one, that the edit makes. 23 tests passed.

Every payload a test produces is held to its schema, both ways verify-every-payload-is-held-to-its-schema

Every helper in crates/htmlspec-cli/tests/ that runs the binary passes its output to support::held, which validates the payload against its operation's published schema and against the suite's reading of it, every object refusing an undeclared property. cargo test -p htmlspec-cli ran every integration test through it and passed. an_added_property_passes_the_published_schema_and_fails_the_suites_reading shows the two readings part on an added property, and every_published_payload_schema_admits_an_undeclared_property holds every published object open.

Every declared field appears in a payload verify-every-declared-field-is-produced

tests/payloads.rs's every_field_a_payload_schema_declares_is_produced builds the projects that write the rare fields, including a run refused for a missing prerequisite, and fails on any of the 251 declared properties no payload carried. It passed. With list's follows no longer written, it failed naming four uncovered properties.

Earlier contract versions still validate verify-earlier-contract-versions-still-validate

The conformance suite's no_document_gains_an_error_under_the_newest_contract_version validates every fixture under the version it declares and under 1.0.0, and requires no new error. The schema's tests require 0.1.0 to 0.7.0 and 1.0.0 accepted and other versions refused. The CLI's tests require a new document and a run's record, head and masthead, to declare 1.0.0. All passed.

That a later 1.x release reports no new error on a document an earlier one accepts: no later release exists, and while no rule reads the declared version the conformance test cannot fail, so review of each change to what a fixture expects holds that promise.

The repository's checks pass at 1.0.0 verify-the-repository-checks-pass-at-1-0-0

scripts/check ran its fourteen stages and passed, and publish/export --ref HEAD --dry-run against an empty local repository ran the same checks inside the exported tree and passed. scripts/check-release found the version, the five pins, and the changelog at 1.0.0.
