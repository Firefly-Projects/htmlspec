What this runbook is for

A runbook is a procedure run again and again, so it is never archived the way a change is. This specification states what every run must record and what a run needs of the machine. The steps themselves are in tasks.html, beside it.

Requirements

Each requirement here is an obligation on every run, not on the project, and each run's record holds an outcome for it. Every unit stays unchanged, because this is the canonical procedure: a change to it is a new release of the runbook, with a new VERSION and a changelog heading.

Every run records what it observed req-example

A run MUST record what each step observed, precisely enough that someone who was not there can tell what happened.

A requirement can also state what a run needs of the machine, as a note whose text begins preflight/v1. htmlspec preflight checks it, and so does every start of a run. This one is shown as a sample rather than declared, so the new runbook starts on any machine:

Given
A run whose step finished without a note of what it saw.
