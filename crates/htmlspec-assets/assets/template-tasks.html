Tasks

Each task is one unit of work, individually addressable, so a state change is a change to one unit rather than to a list.

  • The example task task-example

    State the work in a sentence someone else could pick up. A task in a change may reference the requirement it serves with data-refs, once that requirement exists in the change's specification or in the project's accepted specifications.

  • An abandoned task task-dropped-example

    A dropped task states why it was dropped. Without the reason it records that something was abandoned and not what the decision was.

  • A task done another way task-deviation-example

    A done task whose work departed from its words states what was done instead, and which part, if only part was. The heading keeps the words as they were planned, because designs and evidence cite a task by them. A task done as its words say states no deviation, and a task whose work did not happen is dropped with its reason.
